# 기준 저장소 `jobprep` 안내 (집필자용, 2026-11-14)

이 문서는 「AI에이전트 기획 및 개발」 2~13장의 집필자가 기준 저장소 `jobprep/`의 구조를 빠르게 파악하도록 정리한 것이다. 학생에게 배포하는 키트 안 문서가 아니며, 학생용 설명은 `jobprep/README.md`에 있다. 근거 문서는 `기획/LLM과목/`의 집필 기준 v1.0(7절, 8절), 설계안 v1.0(2.3절, 3.3절), 편성표 v1.0(§6)이다.

## 5. 확인하지 못한 것

- 실제 Anthropic API 호출(집필 기준 8절에 따라 하지 않음). 실제 모델이 `summary_v1`에 JSON만 내는지, `ask_v1`에 근거 번호를 붙이는지는 수업 전 리허설에서 확인한다. Haiku 5.5는 적응형 사고가 켜져 있어 `max_tokens`(2048)에 사고 토큰이 포함된다. 응답이 잘리면 `stop_reason=max_tokens`로 `LLMError`가 난다.
- Ollama 임베딩. 이 컴퓨터에 Ollama가 없어 대체 구현만 돌렸다. Ollama 기준값 0.5(`MIN_SCORE["ollama"]`)는 2026년판 `rag_chat.py`의 값을 따른 것이며 측정하지 않았다. `EMBED_BACKEND=auto`에서 Ollama가 없으면 첫 질의응답이 4~5초 늦다(연결 시도 3초 제한).
- macOS에서의 실행. 집필 PC는 Windows 11(Git Bash)이다. 고정 포트(웹 8100, API 8000)로 함께 띄운 브라우저 확인은 2026-11-14의 8080 확인 뒤 다시 하지 않았다(`common.js`의 포트 계산은 바뀌지 않았다).
- 명세서의 형식은 앞 과목 6장 강의안이 아직 없어 집필 기준과 설계안의 서술(EARS, REQ-ID, 추적 표)에 맞추어 정하였다. 앞 과목 6장이 다른 형식을 정하면 맞추어야 한다.
- 기업 이름 30개는 지어낸 것이나, 같은 이름의 실제 기업이 없는지는 검색하지 않았다. README와 화면 바닥글에 가상임을 밝혔다.

## 6. 내 PC 기준 정비 (2026-11-17, 사용자 결정 11)

학과 실습 서버를 쓰지 않고 학생 각자의 PC(Windows는 Git Bash, macOS는 기본 셸)에서 실습하게 되어 기준 저장소를 다음과 같이 고쳤다. 2~13장은 이 판을 받는다.

| 파일 | 바꾼 것 |
|---|---|
| `.gitattributes`(새 파일) | `* text=auto eol=lf`. Windows Git의 기본 `core.autocrlf=true`가 줄 끝을 CRLF로 바꾸지 않게 한다. 첫 커밋의 `LF will be replaced by CRLF` 경고(파일마다 한 줄, 48줄)가 없어지고, 6장 이후의 셸 훅이 리눅스 CI에서 CRLF로 깨지지 않는다. 첫 커밋은 49개 파일(전에는 48개), `3273 insertions(+)`이다 |
| `data/jobs.json`, `logs/access.log`, `logs/error.log`, `logs/llm.log` | 줄 끝을 CRLF에서 LF로 바꾸었다(내용은 같다. `git diff --ignore-cr-at-eol`이 빈 출력) |
| `web/js/common.js` | 2~6행의 주석만 고정 포트(API 8000, 웹 8100) 기준으로 고쳤다. 코드는 그대로이다(웹 8101~8199 → API는 100 작은 포트, `?api=번호`, 그 밖은 8000) |
| `.env.example` | 「교수가 발급한 실습용 API 키」 → 각자 Console에서 발급하는 선택 키, 유출 시 Console에서 폐기 |
