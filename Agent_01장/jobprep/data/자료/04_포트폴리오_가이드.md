# 개발 직군 포트폴리오 가이드

이 문서는 실습용 가상 자료이다. 실제 학과의 규정이 아니다.

## 포트폴리오에 넣을 프로젝트

포트폴리오에는 프로젝트를 세 개 안팎으로 고른다. 지원하는 직무와 가까운 프로젝트를 앞에 둔다. 수업 과제만 있으면 과제를 발전시킨 내용(기능 추가, 테스트, 배포)을 함께 보여 준다.

## 저장소 정리

프로젝트마다 GitHub 저장소를 공개하고 README를 쓴다. README에는 프로젝트의 목적, 실행 방법, 사용한 기술, 화면 캡처, 본인이 맡은 부분을 적는다. API 키나 비밀번호가 저장소에 올라가지 않았는지 커밋 기록까지 확인한다.

## 배포 링크

웹 프로젝트는 실제로 열어 볼 수 있는 배포 링크를 붙인다. 정적 웹은 GitHub Pages로 배포할 수 있다. 서류 제출 전에 링크가 열리는지 다른 컴퓨터에서 확인한다. 링크가 열리지 않으면 평가자가 프로젝트를 보지 않는 경우가 많다.

## 팀 프로젝트의 기여 표시

팀 프로젝트는 본인이 기여한 부분을 구체적으로 적는다. 커밋 기록, 풀 리퀘스트, 이슈 링크로 기여를 보여 줄 수 있다. 팀원의 작업을 본인의 것처럼 쓰면 면접에서 드러난다.

## 포트폴리오 검토

포트폴리오 검토는 매 학기 10월에 학과 교수와 현직자가 함께 한다. 검토를 받으려면 9월 마지막 주까지 포트폴리오 링크를 학과 사무실에 제출한다.
