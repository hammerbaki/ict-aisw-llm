# 변형 지시: 공통

> 이 파일은 두 변형(variant-form, variant-chat)에 똑같이 준다. 변형마다 다른 것은 `변형지시_form.md`, `변형지시_chat.md`에만 적는다. 「 」 자리는 자기 저장소에 맞게 바꾼다.

## 기준 문서

- 요구사항 명세: `docs/요구사항명세서.md`의 「자기소개서 피드백」 절(REQ-080~REQ-089). 이 절이 구현의 기준이다.
- 프로젝트 규칙: `CLAUDE.md`. 화면의 공통 규칙: `docs/설계/화면명세.md`.

## 할 일

1. REQ-080~REQ-089를 구현한다. 백엔드는 `api/` 아래 새 모듈과 라우터로, 화면은 `web/` 아래 새 파일로 만든다.
2. LLM 호출은 `api/llm.py`의 `complete()`만 쓴다. `purpose`는 `"feedback_" + 변형 이름`으로 준다.
3. 요구마다 테스트를 하나 이상 `tests/test_feedback_<변형 이름>.py`에 쓴다. 함수 이름은 `test_REQ_0NN_...`(요구 번호 세 자리)으로 시작한다. 모의 모드(`LLM_FAKE=1 python -m pytest`. `pytest.ini`가 `-q`를 이미 준다)에서 통과시킨다.
4. 기존 기능(공고 모아보기, 요약, 질의응답)과 그 테스트를 깨뜨리지 않는다.

## 하지 말 것

- 명세 파일을 고치지 않는다. 명세의 변경은 사람이 한다.
- 다른 변형의 화면이나 API를 만들지 않는다.
- 사용자가 입력한 문항과 답변을 파일이나 기록에 남기지 않는다(REQ-087).

## 보고

끝나면 다음 네 가지를 보고한다.

1. 바꾸거나 만든 파일
2. 요구 ID별 구현 위치(파일과 함수)
3. 명세에 없어 스스로 정한 것의 목록(예: 글자 수를 세는 방식, 이전 결과의 처리)
4. 실행한 검사 명령과 결과
