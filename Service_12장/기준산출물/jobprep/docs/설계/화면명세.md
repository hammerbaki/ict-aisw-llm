# 화면 명세: 취업 준비 지원 서비스(jobprep)

- 판: v1.0 (8장 정답 예시. 학생의 결과가 이와 같을 필요는 없다)
- 입력: `docs/요구사항명세서.md`(v2, 화면 목록), `docs/설계/정보구조.md`, `docs/설계/사용자흐름.md`, `docs/설계/디자인토큰.md`(v1.0)
- 범위: 핵심 화면 4개(SCR-01~04). SCR-05, 06은 10~11장에서 쓴다.
- 이 파일은 기능의 기준이다. 배치는 각 화면의 와이어프레임이 기준이다. 둘이 어긋나면 구현자는 임의로 정하지 않고 묻는다.

## 0. 모든 화면에 공통

| 항목 | 내용 |
|---|---|
| 머리 | 서비스 이름 「jobprep 취업 준비」, 전역 내비게이션(공고, 내 지원 일정, 자기소개서, 취업 자료 묻기). 현재 화면은 `aria-current="page"`. 아직 없는 화면(자기소개서, 취업 자료 묻기)은 비활성으로 보이고 초점을 받지 않는다 |
| 본문 바로가기 | 첫 번째 초점 위치에 「본문 바로가기」 링크. 초점을 받을 때만 보인다 |
| 제목 | 화면마다 `h1` 하나. 제목 단계를 건너뛰지 않는다 |
| 문구의 말투 | 화면 문구는 해요체. 버튼은 동사로 끝낸다(「일정 저장」, 「요약 만들기」) |
| 중단점 | 기본(모바일) 1열, 40rem(640px) 이상 2열, 64rem(1024px) 이상 3열 |
| 초점 표시 | `color-focus` 3px 테두리, 요소에서 2px 띄움 |
| 누름 영역 | 버튼, 내비게이션, 홀로 놓인 링크는 높이 44px(`size-target-min`) 이상 |
| 적용 요구 | REQ-13(키보드), REQ-14(대비), REQ-15(320px) |

## SCR-01. 공고 목록

### 1) 개요

| 항목 | 내용 |
|---|---|
| 화면 ID | SCR-01 |
| 목적 | 사용자가 조건에 맞는 공고를 마감일이 가까운 순으로 훑어보고 하나를 고른다 |
| 관련 요구 | REQ-01, REQ-02, REQ-03, REQ-04 |
| 들어오는 길 | 서비스 첫 화면. 전역 내비게이션 「공고」 |
| 나가는 길 | 공고 제목 → SCR-02 |
| 사용자 흐름 | F1의 1~2단계 |

### 2) 와이어프레임

```text
+----------------------------------+
| jobprep 취업 준비                |
| [공고] [내 지원 일정] 자기소개서 …|
+----------------------------------+
| 채용 공고                    (h1)|
| 마감일이 가까운 공고부터 보여요  |
|                                  |
| 검색어                           |
| 공고 제목, 회사명, 직무에서 찾아요|
| [______________________________] |
| 지역            직무             |
| [전체      v]   [전체      v]    |
|                                  |
| 공고 6건                (상태)   |
| +------------------------------+ |
| | 웹 프론트엔드 개발 신입  (h2)| |
| | 한빛데이터(가상)·서울·개발   | |
| | 마감 2027-04-11(일) [D-2]    | |
| +------------------------------+ |
| +------------------------------+ |
| | AI 서비스 운영 보조          | |
| | …                            | |
+----------------------------------+
```

넓은 화면(40rem 이상): 검색어·지역·직무가 한 줄(2:1:1), 카드 2열. 64rem 이상: 카드 3열.

### 3) 구성 요소

| 번호 | 요소 | 종류 | 내용과 규칙 | 관련 요구 |
|---|---|---|---|---|
| 1 | 화면 제목 | 제목(h1) | 「채용 공고」 | |
| 2 | 안내 문장 | 글자 | 정렬 기준을 알린다 | REQ-01 |
| 3 | 검색어 | 입력(search) | 보이는 레이블 「검색어」, 도움말 연결. 입력하는 대로 목록을 거른다 | REQ-02 |
| 4 | 지역 | 선택 | 전체, 서울, 경기, 대전, 부산 | REQ-03 |
| 5 | 직무 | 선택 | 전체, 개발, 운영, 품질 | REQ-03 |
| 6 | 결과 수 | 상태 영역 | 「공고 N건」. 조건이 바뀔 때마다 갱신 | REQ-02, REQ-03 |
| 7 | 공고 카드 목록 | 목록 | 카드마다 제목(링크, h2), 회사·지역·직무, 마감일과 마감 3일 이내 표시. 마감일 오름차순 | REQ-01 |

### 4) 상태

| 상태 | 언제 | 화면에 보이는 것 | 문구 |
|---|---|---|---|
| 기본 | 공고가 1건 이상 | 결과 수와 카드 목록 | 「공고 N건」 |
| 로딩 | 공고를 불러오는 동안 | 카드 자리에 회색 상자 3개, 영역에 `aria-busy="true"` | 「공고를 불러오는 중이에요」 |
| 빈 상태 | 조건에 맞는 공고가 0건 | 안내 상자: 제목, 바꾸는 방법, 「조건 모두 지우기」 버튼 | 「조건에 맞는 공고가 없어요」, 「검색어를 줄이거나 지역·직무를 「전체」로 바꿔 보세요.」 |
| 오류 | 불러오기 실패 | 오류 상자(`role="alert"`)와 「다시 불러오기」 | 「공고를 불러오지 못했어요. 인터넷 연결을 확인한 뒤 다시 불러와 주세요.」 |

### 5) 상호작용

| 사용자 동작 | 시스템 반응 | 관련 요구 |
|---|---|---|
| 검색어를 입력한다 | 목록을 즉시 거르고 결과 수를 갱신한다. 화면은 옮기지 않는다 | REQ-02 |
| 지역이나 직무를 바꾼다 | 위와 같다 | REQ-03 |
| 「조건 모두 지우기」를 누른다 | 조건을 비우고 전체 목록을 보이며, 초점을 검색어 칸으로 옮긴다 | REQ-04 |
| 공고 제목을 누른다 | SCR-02로 간다 | |

### 6) 접근성 메모

| 항목 | 내용 | WCAG |
|---|---|---|
| 초점 순서 | 본문 바로가기 → 서비스 이름 → 내비게이션 → 검색어 → 지역 → 직무 → 카드 제목들 | 2.4.3 |
| 상태 알림 | 결과 수 문장은 `role="status"`. 필터를 바꿔도 초점은 그대로 두고 수만 읽힌다 | 4.1.3 |
| 입력 중 화면 전환 금지 | 선택을 바꿔도 다른 화면으로 가지 않는다 | 3.2.2 |
| 마감 임박 | 색 상자와 함께 「마감 D-2」 글자로 알린다 | 1.4.1 |
| 검색 영역 | `role="search"`와 `aria-label`로 랜드마크를 둔다 | 1.3.1 |

### 7) 열린 질문

- 공고가 수백 건이 되면 쪽 나누기와 「더 보기」 중 무엇을 쓰는가 → 9장에서 실제 데이터 규모를 보고 정한다.

## SCR-02. 공고 상세

### 1) 개요

| 항목 | 내용 |
|---|---|
| 화면 ID | SCR-02 |
| 목적 | 사용자가 공고의 핵심 조건을 확인하고, 필요하면 요약을 읽고 원문과 대조한 뒤 일정에 추가한다 |
| 관련 요구 | REQ-05, REQ-06, REQ-07, REQ-08, REQ-09 |
| 들어오는 길 | SCR-01의 공고 제목, SCR-03의 일정 제목 |
| 나가는 길 | 「일정에 추가」 → SCR-04(값이 채워진 채로), 「공고 목록으로」 → SCR-01 |
| 사용자 흐름 | F1의 3~4단계, F2 전체 |

### 2) 와이어프레임

```text
+----------------------------------+
| (머리와 내비게이션)              |
+----------------------------------+
| < 공고 목록으로                  |
| 웹 프론트엔드 개발 신입      (h1)|
|                                  |
| 공고 정보                    (h2)|
| 회사     한빛데이터(가상)        |
| 근무 지역 서울                   |
| 직무     개발                    |
| 마감     2027-04-11(일) [D-2]    |
| 자격 요건                    (h3)|
| · HTML·CSS·자바스크립트 기초     |
| · …                              |
| [일정에 추가]  [원문 보기]       |
|                                  |
| 공고 원문                    (h2)|
| (문단 1) …                       |
| (문단 2) …                       |
|                                  |
| +- 공고 요약 ----------------(h2)+
| | 원문을 다섯 줄 이내로 줄이고…  |
| | [요약 만들기]                  |
| | (상태 문장)                    |
| | AI가 만든 요약이에요. …        |
| | 1. … [원문 1문단]              |
| | 2. … [원문 2문단]              |
| +--------------------------------+
+----------------------------------+
```

넓은 화면(64rem 이상): 왼쪽에 공고 정보와 원문(3), 오른쪽에 요약(2)을 나란히 둔다. 좁은 화면에서는 요약이 원문 아래로 간다.

### 3) 구성 요소

| 번호 | 요소 | 종류 | 내용과 규칙 | 관련 요구 |
|---|---|---|---|---|
| 1 | 공고 목록으로 | 링크 | 높이 44px | |
| 2 | 공고 제목 | 제목(h1) | | REQ-05 |
| 3 | 공고 정보 | 정의 목록 | 회사, 근무 지역, 직무, 마감(마감 3일 이내 표시) | REQ-05 |
| 4 | 자격 요건 | 목록 | 원문에서 뽑은 항목 | REQ-05 |
| 5 | 일정에 추가 | 주 버튼(링크) | SCR-04로 가며 회사명, 제목, 마감일을 넘긴다 | REQ-09 |
| 6 | 원문 보기 | 보조 버튼(링크) | 원문 절로 이동 | REQ-05 |
| 7 | 공고 원문 | 문단 | 문단마다 번호를 둔다(`p1`, `p2` …). 요약의 근거 링크가 가리키는 자리 | REQ-06 |
| 8 | 요약 만들기 | 주 버튼 | 생성 중에는 잠기고 「요약을 만드는 중」, 완료 뒤 「다시 만들기」, 실패 뒤 「다시 시도」 | REQ-06, REQ-07, REQ-08 |
| 9 | 요약 상태 | 상태 영역 | 생성 중, 완료, 실패를 알린다 | REQ-07 |
| 10 | 요약 결과 | 번호 목록 | 다섯 줄 이내. 줄 끝마다 근거 링크 「원문 N문단」. 위에 「AI가 만든 요약」 고지 | REQ-06 |

### 4) 상태

| 상태 | 언제 | 화면에 보이는 것 | 문구 |
|---|---|---|---|
| 기본 | 처음 열었을 때 | 요약 영역에 설명과 「요약 만들기」 | 「원문을 다섯 줄 이내로 줄이고, 줄마다 근거가 된 원문 문단을 달아요.」 |
| 생성 중 | 요청 뒤 응답 전 | 버튼에 돌아가는 표시, `aria-busy`, `aria-disabled` | 「요약을 만드는 중이에요. 보통 10초 안에 끝나요.」 |
| 완료 | 응답 성공 | AI 고지, 요약 목록, 근거 링크, 버튼 「다시 만들기」 | 「AI가 만든 요약이에요. 마감일과 자격 요건은 원문 문단을 눌러 확인해 주세요.」 |
| 오류 | 응답 실패, 한도 초과 | 오류 상자, 버튼 「다시 시도」. 원문은 그대로 | 「요약을 만들지 못했어요. 잠시 뒤 「다시 시도」를 눌러 주세요. 원문은 그대로 읽을 수 있어요.」 |

### 5) 상호작용

| 사용자 동작 | 시스템 반응 | 관련 요구 |
|---|---|---|
| 「요약 만들기」를 누른다 | 생성 중 상태로 바꾸고 요청을 한 번 보낸다 | REQ-06, REQ-07 |
| 생성 중에 버튼을 다시 누른다 | 아무 일도 하지 않는다 | REQ-07 |
| 근거 링크 「원문 N문단」을 누른다 | 해당 문단으로 스크롤하고 초점을 옮기며 문단을 강조한다 | REQ-06 |
| 「다시 만들기」를 누른다 | 이전 요약을 지우고 생성 중 상태로 간다 | REQ-06 |
| 「일정에 추가」를 누른다 | SCR-04로 간다(값 채움) | REQ-09 |

### 6) 접근성 메모

| 항목 | 내용 | WCAG |
|---|---|---|
| 생성 중 버튼 | `disabled` 대신 `aria-disabled="true"`로 잠근다. 초점이 버튼에서 사라지지 않게 하기 위해서다 | 2.4.3, 4.1.2 |
| 상태 알림 | 요약 상태 문장은 `role="status"`. 완료 시 「요약을 만들었어요. 5줄이에요.」 | 4.1.3 |
| 근거 링크 이름 | 「출처」가 아니라 「원문 3문단」처럼 가리키는 곳을 쓴다 | 2.4.4 |
| 움직임 | 돌아가는 표시는 `prefers-reduced-motion`이면 멈춘다 | 2.3.3(AAA, 권장) |

### 7) 열린 질문

- 요약 한 번에 드는 비용과 하루 요청 한도를 사용자에게 보일 것인가 → 10장에서 비용을 잰 뒤 정한다.
- 요약이 틀렸다고 알리는 「의견 보내기」를 둘 것인가 → 13장 사용성 평가 뒤 정한다.

## SCR-03. 지원 일정

### 1) 개요

| 항목 | 내용 |
|---|---|
| 화면 ID | SCR-03 |
| 목적 | 사용자가 지원할 공고를 마감일 순으로 보고 마감이 임박한 것을 놓치지 않는다 |
| 관련 요구 | REQ-10, REQ-12 |
| 들어오는 길 | 전역 내비게이션 「내 지원 일정」, SCR-04 저장 뒤 |
| 나가는 길 | 일정 제목 → SCR-02, 「일정 직접 등록」 → SCR-04 |
| 사용자 흐름 | F1의 5단계 |

```text
+----------------------------------+

| +------------------------------+ |
+----------------------------------+
```

| 사용자 동작 | 시스템 반응 | 관련 요구 |
|---|---|---|
| 「삭제」를 누른다 | 확인 창: 「「공고 제목」 일정을 삭제할까요? 삭제하면 되돌릴 수 없어요.」 | REQ-12 |
| 확인 창에서 확인 | 카드를 지우고 「일정을 삭제했어요」를 알리며 초점을 화면 제목으로 옮긴다 | REQ-12 |
| 확인 창에서 취소 | 아무것도 바꾸지 않는다 | REQ-12 |

### 6) 접근성 메모

| 항목 | 내용 | WCAG |
|---|---|---|
| 삭제 버튼 이름 | 화면에는 「삭제」만 보이지만 `aria-label`을 「삭제: 회사 공고 제목」으로 두어 어느 일정인지 구별한다. 보이는 글자 「삭제」로 이름을 시작해야 「삭제 누르기」 같은 음성 조작이 맞는다 | 2.5.3, 2.4.6 |
| 삭제 뒤 초점 | 지워진 카드에 있던 초점이 문서 처음으로 튀지 않도록 화면 제목(`tabindex="-1"`)으로 옮긴다 | 2.4.3 |

### 7) 열린 질문

- 지원 단계를 이 화면에서 바로 바꿀 수 있게 할 것인가 → 프로토타입 리뷰에서 의견을 받는다.

## SCR-04. 지원 일정 등록

### 1) 개요

| 항목 | 내용 |
|---|---|
| 화면 ID | SCR-04 |
| 목적 | 사용자가 지원할 공고의 마감일과 단계를 저장한다 |
| 관련 요구 | REQ-09, REQ-11 |
| 들어오는 길 | SCR-02 「일정에 추가」(값 채움), SCR-03 「일정 직접 등록」(빈 양식) |
| 나가는 길 | 저장 성공 → SCR-03(완료 알림), 「취소」 → SCR-03 |
| 사용자 흐름 | F1의 4~5단계 |

### 2) 와이어프레임

```text
+----------------------------------+
| (머리와 내비게이션)              |
+----------------------------------+
| < 내 지원 일정으로               |
| 지원 일정 등록               (h1)|
| +- 입력을 확인해 주세요 (2건) --+ |  <- 오류가 있을 때만
| | · 회사명을 입력해 주세요.     | |
| | · 마감일이 지났어요. …        | |
| +-------------------------------+ |
| 「필수」 표시가 있는 항목은 …    |
| 회사명 (필수)                    |
| [______________________________] |
| 오류: 회사명을 입력해 주세요.    |
| 공고 제목 (필수)                 |
| [______________________________] |
| 마감일 (필수)                    |
| 공고에 적힌 서류 마감일이에요    |
| [____-__-__                 [달]]|
| 지원 단계                        |
| [관심                        v]  |
| 메모 (선택)                      |
| 200자까지 적을 수 있어요         |
| [______________________________] |
| [일정 저장]  [취소]              |
+----------------------------------+
```

넓은 화면에서도 한 열을 유지한다(양식은 한 열이 빠르다). 본문 최대 폭만 늘어난다.

### 3) 구성 요소

| 번호 | 요소 | 종류 | 내용과 규칙 | 관련 요구 |
|---|---|---|---|---|
| 1 | 오류 요약 | 알림 | 저장을 눌렀는데 오류가 있을 때만. 오류마다 해당 칸으로 가는 링크 | REQ-11 |
| 2 | 회사명 | 입력(text) | 필수. 공고에서 왔으면 채워져 있다 | REQ-09 |
| 3 | 공고 제목 | 입력(text) | 필수. 공고에서 왔으면 채워져 있다 | REQ-09 |
| 4 | 마감일 | 입력(date) | 필수. 오늘 이후. 도움말 「공고에 적힌 서류 마감일이에요」 | REQ-09, REQ-11 |
| 5 | 지원 단계 | 선택 | 관심(기본), 서류 준비, 서류 제출, 면접, 결과 대기 | REQ-09 |
| 6 | 메모 | 여러 줄 입력 | 선택. 200자 | |
| 7 | 일정 저장 | 주 버튼(submit) | | REQ-09 |
| 8 | 취소 | 보조 버튼(링크) | SCR-03으로. 입력은 버린다 | |

### 4) 상태

| 상태 | 언제 | 화면에 보이는 것 | 문구 |
|---|---|---|---|
| 기본 | 처음 열었을 때 | 빈 양식 또는 값이 채워진 양식 | |
| 오류 | 저장을 눌렀는데 규칙에 맞지 않을 때 | 오류 요약(초점 이동), 칸마다 빨간 테두리와 「오류:」로 시작하는 문장. 입력한 값은 남긴다 | 아래 오류 문구 표 |
| 완료 | 저장 성공 | SCR-03으로 가서 완료 알림 | 「지원 일정을 저장했어요.」 |

오류 문구:

| 칸 | 조건 | 문구 |
|---|---|---|
| 회사명 | 비었다 | 회사명을 입력해 주세요. |
| 공고 제목 | 비었다 | 공고 제목을 입력해 주세요. |
| 마감일 | 비었다 | 마감일을 골라 주세요. 예: 2027-04-30 |
| 마감일 | 오늘보다 앞이다 | 마감일이 지났어요. 오늘(YYYY-MM-DD) 이후 날짜를 골라 주세요. |

### 5) 상호작용

| 사용자 동작 | 시스템 반응 | 관련 요구 |
|---|---|---|
| 「일정 저장」을 누른다(오류 있음) | 저장하지 않는다. 오류 요약을 보이고 초점을 옮긴다 | REQ-11 |
| 오류 요약의 항목을 누른다 | 해당 칸으로 초점을 옮긴다 | REQ-11 |
| 「일정 저장」을 누른다(오류 없음) | 저장하고 SCR-03으로 간다 | REQ-09 |
| 칸을 고치는 중 | 오류를 즉시 다시 띄우지 않는다. 검사는 저장을 누를 때 한다 | |

### 6) 접근성 메모

| 항목 | 내용 | WCAG |
|---|---|---|
| 레이블 | 모든 칸에 보이는 레이블. 자리 표시 글자를 레이블로 쓰지 않는다. 필수는 「(필수)」 글자로 | 3.3.2 |
| 오류 연결 | 오류 문장에 id를 주고 입력 칸의 `aria-describedby`에 도움말과 함께 넣는다. `aria-invalid="true"` | 3.3.1, 4.1.2 |
| 고치는 방법 | 오류 문장은 무엇이 틀렸고 어떻게 고치는지를 함께 쓴다 | 3.3.3 |
| 색에만 기대지 않기 | 빨간 테두리와 함께 「오류:」 글자, 굵은 글씨 | 1.4.1 |
| 다시 입력하지 않기 | 공고에서 왔으면 이미 아는 회사명, 제목, 마감일을 채운다 | 3.3.7 |
| 자동 완성 | 회사명 칸에 `autocomplete="organization"` | 1.3.5 |

### 7) 열린 질문

- 같은 공고를 두 번 추가하면 막을 것인가, 알리기만 할 것인가 → 9장 구현 전에 명세서에 요구를 더한다.
