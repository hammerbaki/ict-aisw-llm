# jobprep 프로젝트 규칙 (기준 산출물 견본)

## 개요
- 취업 준비 지원 서비스. 대상 사용자는 전문대학 2학년 취업 준비생이다(페르소나 PS-1 서지후, PS-2 임하람).
- 명세는 `docs/요구사항명세서.md`(현재 판 v6, 태그 `spec-v6`)가 기준이다. 구현 전에 관련 요구(REQ)와 수용 기준(AC)을 읽는다. 명세에 없는 동작을 정해야 하면 구현하되, 보고에 「명세에 없어 정한 것」으로 따로 적는다.
- 백엔드는 `api/`(FastAPI, 앱은 `api/app.py`의 `app`), 화면은 `web/`(빌드 도구 없는 HTML·CSS·자바스크립트)이다. 화면은 `docs/설계/화면명세.md`와 `docs/설계/디자인토큰.md`의 공통 규칙을 따른다.
- LLM 호출은 `api/llm.py`의 `complete()` 한 곳을 지난다(질의응답의 `rag/llm.py`도 이 함수를 부른다). 호출마다 `api/logs/llm_calls.jsonl`에 시각, 변형, 용도, 토큰 수, 걸린 시간이 남는다.

## 실행 (jobprep 폴더에서. 가상 환경은 저장소 맨 위의 `.venv`이며, 켠 터미널에서 실행한다)
- 테스트: `python -m pytest -q`
- 색인(처음 한 번): `EMBED_BACKEND=fallback python -m rag index`
- 서버: `python -m uvicorn api.app:app --port 8000` (웹도 이 서버가 같은 출처에서 보낸다. 서버를 둘 띄울 때만 둘째를 8001로)

## 규칙
- 구현을 바꾸기 전에 명세서의 해당 요구를 먼저 고친다. 명세 변경과 구현은 같은 커밋에 묶고, 커밋 메시지 끝에 요구 ID(예: `REQ-013`)를 적는다.
- `tests/` 아래의 기존 테스트는 고치지 않는다. 새 기능의 테스트는 새 파일로 더한다.
- API 키와 모델 이름을 코드에 쓰지 않는다. 키는 `jobprep/.env`에만 두고(`.gitignore` 처리), 모델은 `LLM_MODEL`로 읽는다.
- LLM을 부르는 코드는 `LLM_FAKE=1`이면 API를 부르지 않아야 한다.
- 사용자가 입력한 글(자기소개서 등)을 파일이나 기록에 남기지 않는다.
- 끝나면 바꾼 파일, 반영한 요구 ID, 사람이 확인할 항목을 보고한다.
