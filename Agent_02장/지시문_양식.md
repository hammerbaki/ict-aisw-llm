# Claude Code 지시문 양식: 테스트 주도 구현 (2장)

이 양식은 동결한 테스트를 통과시키는 구현을 Claude Code에 맡길 때 보내는 지시문이다. 「 」로 표시한 자리를 바꿔 넣고, 나머지 문장은 그대로 둔다. 각 줄이 왜 있는지는 강의안 8절에 있다.

- 보내기 전에 확인한다: 테스트를 채웠고, Red를 확인했고, `python tools/test_guard.py freeze --update`로 동결 기록을 고쳤고, 테스트와 동결 기록을 커밋했다.
- 받은 뒤에 확인한다: 보고의 증거(명령과 출력)를 읽고, 같은 명령을 `[터미널]`에서 직접 실행하고, `git status --short`와 `git diff --stat`로 바뀐 파일을 본다.

## 1. 구현 지시문 (사이클마다 하나)

```text
「REQ-JOB-06」을 구현하라. 요구 문장과 인수 조건은 docs/요구사항명세서.md에 있다.
판정 기준은 「tests/test_closing_within.py」이다. 먼저 이 테스트 파일을 읽어라.

지켜야 할 것
- tests/ 아래의 파일, pytest.ini, conftest.py, tools/test_guard.py는 고치지도, 지우지도, 새로 만들지도 마라.
- 테스트의 기대값을 그대로 돌려주는 코드(하드코딩)나 테스트에서만 맞는 특수 처리를 쓰지 마라. 요구 문장 전체를 만족하는 일반적인 구현을 써라.
- 고칠 곳은 「api/jobs.py와 api/main.py」이다. 다른 파일을 고쳐야 하면 고치기 전에 까닭을 말하고 멈춰라.
- git add, git commit, git restore, git stash 같은 git 명령은 쓰지 마라. 커밋은 내가 한다.
- 테스트가 틀렸다고 생각되거나, 요구 문장과 테스트가 어긋나거나, 통과시킬 수 없으면 고치지 말고 그렇게 보고하라.

완료 조건
- python -m pytest -q 의 마지막 줄이 「N」 passed이고 failed와 error가 없다.
- python tools/test_guard.py check 가 TEST_UNCHANGED를 출력한다.

보고 형식
- 고친 파일과 바꾼 내용의 요약(파일마다 한두 줄)
- 위의 두 명령을 실행한 그대로의 마지막 줄
- 요구 문장 가운데 테스트가 확인하지 않는 부분이 있으면 그 부분
```

## 2. 리팩터링 지시문 (세 요구를 모두 통과시킨 뒤)

```text
동작은 바꾸지 말고 api/jobs.py와 api/main.py의 구조만 다듬어라.
- 「요약 본문과 질문의 길이 검사가 엔드포인트 안에 따로 들어 있다. 같은 규칙을 한 곳에서 정하도록 고쳐라.」
- 테스트와 테스트 설정은 고치지 마라. git 명령은 쓰지 마라.
- 고친 뒤 python -m pytest -q 와 python tools/test_guard.py check 를 실행해 마지막 줄을 그대로 보여라.
- 다듬을 것이 없다고 판단하면 고치지 말고 그렇게 보고하라.
```

## 3. 실패했을 때 다시 보내는 지시문

`git restore`로 실패한 시도를 버린 뒤에 보낸다. 앞의 시도에서 무엇이 잘못되었는지를 한 문장으로 알린다.

```text
앞의 시도는 「tests/test_summary_limits.py에서 assert llm_calls == [] 한 줄을 지웠기 때문에」 버렸다. 파일은 동결한 상태로 되돌렸다.
「그 단언은 요구의 "LLM을 부르지 않고"를 확인한다.」 아래 지시문의 조건을 지켜서 처음부터 구현하라. 통과시킬 수 없으면 고치지 말고 까닭을 보고하라.
```

이어서 1번 지시문 전체를 그 사이클의 값으로 붙인다(강의안 11-5절).
