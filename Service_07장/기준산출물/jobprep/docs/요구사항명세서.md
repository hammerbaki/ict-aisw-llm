## 2. 개요

### 2.1 가치 제안

전문대학 2학년 취업 준비생이 흩어진 채용 공고를 마감일 순서로 한곳에서 보고, 공고의 자격 요건과 제출 서류를 근거와 함께 요약해 받으며, 자기소개서가 공고의 요구에 맞는지 점검받게 한다.

### 2.2 대상 사용자

- PS-1 서지후: 아르바이트와 병행하며 밤에 휴대폰으로 흩어진 공고를 훑다가 마감 시각을 놓친다. 흩어진 공고와 마감 관리가 가장 큰 불편이다.
- PS-2 임하람: 공고문의 자격 요건과 직무 요구를 해석하지 못해 지원 여부를 정하지 못한다. AI의 정리에 공고문에 없는 내용이 섞여 원문을 다시 읽는다.
- 자기소개서를 혼자 점검하지 못하는 불편(P-03)은 두 페르소나에 모두 있다.

### 2.3 해결할 문제

| ID | 문제 | 이 명세의 기능 |
|---|---|---|
| P-01 | 흩어진 공고와 마감 시각 | F-01, F-02, F-03 |
| P-02 | 공고문의 자격 요건 해석 | F-04 |
| P-03 | 자기소개서의 혼자 점검 | F-05 |

### 2.4 범위

- 포함: 공고 모아보기, 공고 찾기, 관심 공고와 지원 일정, 공고 요약, 자기소개서 피드백, 취업 자료 질의응답.
- 제외: 회원 가입과 로그인, 채용 사이트에 대신 지원하기, 공고 자동 수집(크롤링), 결제. 공고 자료는 수업용 파일로 준다.

## 5. 요구 문장 (EARS)

### F-01 공고 모아보기

- **REQ-001** [상시] 시스템은 공고 목록의 각 행에 제목, 모집기관, 상태, 접수 마감일을 표시해야 한다.
- **REQ-002** [상시] 시스템은 공고 목록을 접수 마감일이 가까운 순서로 정렬해 표시해야 한다.
- **REQ-003** [상태] 접수 마감일까지 남은 날이 3일 이하인 동안, 시스템은 그 공고 행에 「마감 임박」 표시를 붙여야 한다.
- **REQ-004** [원치 않는 동작] 만약 공고 자료 파일을 읽지 못하면, 시스템은 빈 목록 대신 「공고 자료를 불러오지 못했다」는 안내를 표시해야 한다.

### F-02 공고 찾기

- **REQ-005** [사건] 사용자가 상태(접수예정, 접수중, 마감)를 고르면, 시스템은 그 상태의 공고만 표시해야 한다.
- **REQ-006** [사건] 사용자가 검색어를 입력하고 검색을 누르면, 시스템은 제목이나 모집기관에 검색어가 든 공고만 표시해야 한다.
- **REQ-007** [원치 않는 동작] 만약 조건에 맞는 공고가 없으면, 시스템은 「조건에 맞는 공고가 없다」는 안내와 조건 초기화 단추를 표시해야 한다.

### F-03 관심 공고와 지원 일정

- **REQ-008** [사건] 사용자가 공고의 관심 표시를 누르면, 시스템은 그 공고를 관심 공고 목록에 추가해야 한다.
- **REQ-009** [상시] 시스템은 관심 공고와 지원 일정을 브라우저 저장소에 저장해 페이지를 다시 열어도 유지해야 한다.
- **REQ-010** [사건] 사용자가 관심 공고에 지원 일정을 입력하면, 시스템은 모든 관심 공고의 일정을 날짜순 목록으로 표시해야 한다.
- **REQ-011** [상태] 관심 공고가 마감 상태인 동안, 시스템은 그 공고를 관심 목록의 「지난 공고」 묶음에 표시해야 한다.
- **REQ-012** [선택] 브라우저 알림 기능이 포함된 경우, 시스템은 관심 공고의 접수 마감 하루 전에 알림을 보내야 한다.

### F-04 공고 요약

- **REQ-013** [사건] 사용자가 공고의 요약 단추를 누르면, 시스템은 자격 요건, 근무 조건, 제출 서류, 접수 마감일의 네 항목으로 나눈 요약을 표시해야 한다.
- **REQ-014** [상시] 시스템은 공고 요약의 각 항목 아래에 그 내용의 근거가 된 공고 원문의 문장을 함께 표시해야 한다.
- **REQ-015** [원치 않는 동작] 만약 공고 원문에 요약 항목의 정보가 없으면, 시스템은 그 항목에 「공고에 없음」을 표시해야 한다.
- **REQ-016** [상태] 요약을 만드는 동안, 시스템은 진행 표시를 보이고 요약 단추를 비활성 상태로 두어야 한다.

### F-05 자기소개서 피드백

- **REQ-017** [사건] 사용자가 자기소개서 답과 관심 공고 하나를 고르고 피드백을 요청하면, 시스템은 공고의 자격 요건과 대조한 피드백을 세 항목 이내로 표시해야 한다.
- **REQ-018** [원치 않는 동작] 만약 자기소개서 답이 비어 있으면, 시스템은 피드백을 요청하지 않고 「답을 먼저 입력한다」는 안내를 표시해야 한다.
- **REQ-019** [상시] 시스템은 자기소개서 본문을 피드백 응답을 만든 뒤 서버에 보관하지 않아야 한다.

### F-06 취업 자료 질의응답

- **REQ-020** [사건] 사용자가 취업 자료에 관한 질문을 보내면, 시스템은 학과 취업 자료에서 찾은 근거 문서의 이름과 함께 답을 표시해야 한다.
- **REQ-021** [원치 않는 동작] 만약 질문에 답할 근거를 자료에서 찾지 못하면, 시스템은 추측한 답 대신 「자료에 없다」고 답해야 한다.

### 공통 품질 요구

- **REQ-022** [상시] 시스템은 LLM API 키를 브라우저에 전달되는 코드와 저장소에 두지 않아야 한다.
- **REQ-023** [복합] 모의 모드가 켜진 동안 사용자가 요약이나 피드백을 요청하면, 시스템은 LLM API를 부르지 않고 정해진 견본 응답을 표시해야 한다.

## 6. 수용 기준

형식: 「(전제) ~일 때 (행동) ~하면 (결과) ~이다」. 수용 기준의 ID는 `AC-<요구 번호>-<순번>`이다.

- **AC-001-1** 공고 10건이 든 자료로 목록을 열면, 10행이 보이고 각 행에 제목, 모집기관, 상태, 접수 마감일의 네 칸이 모두 채워져 있다.
- **AC-002-1** 마감일이 11-20, 11-15, 11-30인 공고 셋이 있을 때 목록을 열면, 11-15, 11-20, 11-30의 순서로 보인다.
- **AC-003-1** 시스템 날짜가 11-14이고 마감일이 11-17인 공고가 있을 때 목록을 열면, 그 행에 「마감 임박」이 보인다. 마감일이 11-18인 공고에는 보이지 않는다.
- **AC-004-1** 공고 자료 파일을 지운 뒤 목록을 열면, 「공고 자료를 불러오지 못했다」가 보이고 오류 화면이 나오지 않는다.
- **AC-005-1** 접수중 3건, 마감 7건이 있을 때 「접수중」을 고르면, 3행만 보이고 모든 행의 상태가 접수중이다.
- **AC-006-1** 「공무직」을 검색하면, 제목이나 모집기관에 「공무직」이 든 공고만 보인다.
- **AC-007-1** 「없는검색어123」을 검색하면, 「조건에 맞는 공고가 없다」와 조건 초기화 단추가 보인다.
- **AC-008-1** 공고 하나의 관심 표시를 누르면, 관심 공고 목록에 그 공고가 하나 늘어난다.
- **AC-009-1** 관심 공고 둘을 추가하고 페이지를 새로 고치면, 관심 공고 둘이 그대로 있다.
- **AC-010-1** 관심 공고 둘에 면접일 11-25와 11-21을 적으면, 일정 목록에 11-21, 11-25의 순서로 보인다.
- **AC-011-1** 관심 공고 가운데 마감 상태인 공고는 「지난 공고」 묶음에만 보인다.
- **AC-012-1** 알림 기능을 켠 판에서 마감 하루 전 날짜로 시계를 맞추면, 알림이 한 번 뜬다.
- **AC-013-1** 견본 공고 하나의 요약 단추를 누르면, 네 항목의 제목이 모두 보인다.
- **AC-014-1** 요약의 각 항목 아래 근거 문장이 공고 원문에 그대로 들어 있다(문자열 대조).
- **AC-015-1** 제출 서류가 없는 견본 공고를 요약하면, 제출 서류 항목에 「공고에 없음」이 보인다.
- **AC-016-1** 요약 응답이 2초 걸리도록 늦춘 모의 모드에서 요약 단추를 누르면, 응답이 올 때까지 진행 표시가 보이고 단추를 다시 누를 수 없다.
- **AC-017-1** 자기소개서 답과 공고를 고르고 피드백을 요청하면, 피드백이 1~3항목 보인다.
- **AC-018-1** 답 칸을 비운 채 피드백을 요청하면, 안내가 보이고 서버 요청 기록이 늘지 않는다.
- **AC-019-1** 피드백을 받은 뒤 서버의 저장 폴더와 기록 파일에 자기소개서 본문이 없다.
- **AC-020-1** 「학과 취업 박람회는 언제인가」를 물으면, 답 아래에 근거 문서 이름이 하나 이상 보인다.
- **AC-021-1** 「학교 식당 메뉴는 무엇인가」를 물으면, 「자료에 없다」고 답한다.
- **AC-022-1** 저장소 전체에서 키 형식의 문자열을 찾으면 0건이고, 브라우저 개발자 도구의 소스에도 없다.
- **AC-023-1** `LLM_FAKE=1`로 서버를 켜고 요약을 요청하면, 견본 응답이 보이고 API 호출 기록이 0건이다.
