# jobprep 프로젝트 규칙

## 이 프로젝트

- 취업 준비 지원 서비스. 대상 사용자는 전문대학 2학년 취업 준비생이다(페르소나 PS-1, PS-2).
- 기준 문서는 `docs/요구사항명세서.md`(현재 판 v1.0, 태그 `spec-v1`)이다. 작업을 시작하기 전에 관련 REQ와 수용 기준(AC)을 읽는다.
- 요구가 어느 문제에서 왔는지는 `docs/추적표.md`에 있다.

## 명세 규칙

- 명세에 없는 기능을 만들지 않는다. 명세가 정하지 않은 것(문구, 기준 값, 오류 처리)은 구현하지 말고 질문 목록으로 보고한다.
- 동작을 바꾸는 요청은 명세에서 시작한다. 해당 REQ를 고치고 「변경 이력」에 한 줄을 적은 뒤 구현한다.
- 요구 문장은 EARS 문형(상시, 사건, 상태, 선택, 원치 않는 동작, 복합)으로 쓰고, 주체는 「시스템」이다.
- 명세나 추적표를 고친 뒤 `python tools/ears_check.py docs/요구사항명세서.md --trace docs/추적표.md --problems ../ch05/문제정의.md`를 실행해 오류 0건을 확인한다.
- 구현이 끝난 요구는 수용 기준으로 확인하고, 확인한 방법을 추적표의 「구현·검사」 열에 적는다.

## 작업 방식

- 여러 파일을 바꾸는 작업은 계획 모드에서 계획을 먼저 보이고 승인을 받는다. 계획에는 관련 REQ ID를 적는다.
- 한 커밋에는 한 가지 변경만 담고, 커밋 메시지 끝에 관련 REQ ID를 적는다. 예: `공고 상태 거르기 (REQ-005)`
- 명세를 바꾼 커밋과 그 명세를 구현한 커밋은 같은 풀 리퀘스트에 둔다.

## 기술 제약 (9장 이후에 채운다)

- 프런트엔드: 빌드 도구 없는 HTML, CSS, 자바스크립트. 위치는 `web/`.
- 백엔드: FastAPI. 위치는 `api/`. LLM을 부르는 코드는 `LLM_FAKE=1`이면 API를 부르지 않는다.

## 하지 않는 것

- API 키, 비밀번호, 실제 개인 정보를 파일에 쓰거나 커밋하지 않는다. 키는 저장소 밖의 `.env`에만 둔다.
- 자기소개서 견본에 실명과 연락처를 쓰지 않는다.
- `docs/요구사항명세서.md`의 「변경 이력」에 있는 지난 줄을 지우거나 고치지 않는다.
