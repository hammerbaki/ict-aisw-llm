## 6. 이 결과의 한계

- 모의 응답을 재생한 결과이므로 모델의 실제 성능이 아니다. 실제 점수는 교수 시연의 실행 기록(학생용 11-10)에서 읽어 적는다.
- 실제 호출 결과도 한 번의 실행이다. 같은 판본을 세 번 실행해 점수의 흔들림을 본 뒤 채택한다.

## 7. 웹 연결에서 만난 문제와 해결

- 증상: 9장에서 하던 대로 `python -m http.server 8100 --bind 127.0.0.1 --directory web`으로 웹을 띄우고 `http://localhost:8100/detail.html?id=JOB-003`에서 「요약 보기」를 누르니 「요약을 만들지 못했다. 오류 501」이 나왔다. 웹을 띄운 터미널에는 `"POST /api/summary HTTP/1.1" 501 -`이 찍혔고, API 서버(8000)의 터미널에는 아무 기록도 없었다.
- 원인: `summary.js`는 `/api/summary`를 페이지와 같은 출처로 보낸다. 페이지가 8100에서 왔으므로 요청도 8100의 `http.server`로 갔고, `http.server`는 파일만 보내는 서버라 POST를 처리하지 못해 501(Unsupported method)을 돌려주었다. 요청이 API 서버에 닿지 않았다.
- 해결: 웹을 API 서버의 주소 `http://localhost:8000/detail.html?id=JOB-003`으로 열었다. API 서버가 `web/`을 같은 출처에서 보내므로 요청이 API 서버로 간다. API 서버 터미널에 `"POST /api/summary HTTP/1.1" 200 OK`가 찍히고 요약이 보였다. 8100의 `http.server`는 끄고, `netstat -ano | findstr :8100`이 빈 출력인 것을 보았다.
- 고르지 않은 해결과 그 까닭: `summary.js`에 `http://localhost:8000/api/summary`를 적으면 `WEB_ORIGIN`(기본 `http://localhost:8100`)의 CORS 허락으로 동작하지만, 주소가 웹 코드에 박혀 배포할 때마다 고쳐야 하고 출처마다 CORS 허락을 늘려야 한다. 같은 출처로 여는 편이 단순하다.
