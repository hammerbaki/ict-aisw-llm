# 기능 명세: 「대상 앱의 이름과 판」의 「기능 이름」

> 11장 1-5에서 쓴다. 복사해 `~/llm-service-lab/ch11/기능명세.md`로 쓴다. 요구는 4장의 EARS 문형으로 쓰고, 요구마다 근거의 종류를 하나 붙인다.
>
> - **확인**: 코드의 파일과 줄을 직접 열어 문장과 맞는지 보았다.
> - **추측**: 관찰이나 분석 도구의 결과에서 짐작했으나 코드로 확인하지 못하였다.
> - **정함**: 원본에 없거나 원본과 다르게, 재구현에서 정하였다. 까닭을 적는다.

- 대상: 「이름, 판, 저장소 주소, 커밋」 · 사용권: 「LICENSE 첫 줄」
- 분석한 날: 「YYYY-MM-DD」 · 근거: 「관찰 기록, 코드 읽기(grep), REA 정적 분석, Claude Code」
- 재구현 매체: 「정적 웹(HTML, CSS, JavaScript)」
- 매체 차이: 「원본은 무엇으로 하고 웹은 무엇으로 하는가. 예: 파일 → 브라우저 저장소」

## 1. 경로

화면의 조작에서 저장소까지의 경로를 차례로 적는다(11장 1-1의 그림).

```text
「화면의 조작」 → 「렌더러의 함수(파일:줄)」 → 「통로 이름」 → 「주 프로세스의 처리(파일:줄)」 → 「파일 또는 운영체제」
```
