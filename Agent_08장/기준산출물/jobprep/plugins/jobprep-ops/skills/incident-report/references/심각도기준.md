# 심각도 기준

`jobprep` 운영팀이 장애 보고서의 심각도를 정할 때 쓰는 기준이다. 수업용으로 단순하게 만든 것이며, 실제 서비스는 사용자 수와 계약(SLA)에 따라 기준을 따로 정한다. 위에서부터 차례로 보고 처음 맞는 등급을 쓴다.

| 등급 | 조건 (하나라도 맞으면) | 예 |
|---|---|---|
| SEV1 | 공고 목록(`/api/jobs`)이 5xx를 낸다. 또는 LLM을 쓰는 두 기능(요약, 질의응답)이 함께 30분 넘게 실패한다. 또는 키나 개인 정보가 응답이나 기록에 드러난다 | 서버가 뜨지 않아 목록이 열리지 않음 |
| SEV2 | LLM 기능 하나가 30분 안에 5xx를 3건 이상 낸다. 또는 인증 오류(`AuthenticationError`)가 한 건이라도 있다 | 요약이 한도 초과로 연속 실패 |
| SEV3 | 5xx가 3건 미만이다. 또는 응답이 느리지만(5,000ms 이상) 실패는 없다 | 질의응답이 한 시간 동안 느림 |

## 판단에 쓰는 설명

- **인증 오류를 SEV2로 두는 까닭.** 키가 만료되었거나 잘못 바뀐 것이므로, 사람이 키를 고칠 때까지 같은 기능의 모든 호출이 실패한다. 기록에 남은 건수가 적어도 그 시각 이후 사용자가 적었을 뿐일 수 있다.
- **한도 초과(`RateLimitError`)를 SEV2로 두는 까닭.** 사용자 요청이 몰린 시간에 생기므로, 실패한 요청 수가 곧 영향받은 사용자 수에 가깝다. 재시도와 대기열은 8장(루프와 재시도 상한)에서 다룬다.
- **지연을 SEV3에 두는 까닭.** 사용자는 답을 받았다. 다만 같은 지연이 다음 날에도 나오면 등급을 올린다.
- 기준이 맞지 않는 사건(예: 4xx만 늘었다)은 등급을 억지로 붙이지 않고 보고서 요약에 "심각도 판단 확인 필요"로 적는다. 이 경우에도 서식 검사를 통과하려면 가장 낮은 SEV3를 적고 사유를 쓴다.
