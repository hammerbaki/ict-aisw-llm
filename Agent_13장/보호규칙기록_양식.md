# 보호 규칙 설정 기록

이 양식의 내용을 `docs/운영/배포점검표.md`의 끝에 「3. 보호 규칙」 절로 붙인다(파일을 따로 만들지 않는다).
화면에서 설정한 값을 그대로 옮기고, 설정 화면의 캡처 대신 `gh api`로 읽은 결과를 붙인다.

## 3. 보호 규칙

- 설정한 날: 「YYYY-MM-DD」
- 방식: 「규칙 집합(Rulesets) 또는 예전 방식의 보호 브랜치 규칙」
- 대상: 「기본 브랜치(main)」
- 우회 허용 목록(bypass list): 「비어 있음 또는 누구」

| 규칙 | 설정 값 | 까닭(이 규칙이 막는 것) |
|---|---|---|
| 삭제 금지(Restrict deletions) | 「켬」 | 「」 |
| 강제 푸시 금지(Block force pushes) | 「켬」 | 「」 |
| PR 필수(Require a pull request before merging) | 「켬, 승인 1」 | 「」 |
| 새 커밋이 오면 승인 무효(Dismiss stale approvals) | 「」 | 「」 |
| 대화 해결 필수(Require conversation resolution) | 「」 | 「」 |
| 필수 상태 검사(Require status checks to pass) | 「test, eval, secrets, rules」 | 「」 |
| 최신 상태 필수(Require branches to be up to date) | 「」 | 「」 |

### 확인

```text
「bash ops/protect/set_protection.sh show 의 출력을 붙인다」
```

- 보호 규칙이 막은 것을 본 적이 있는가: 「PR 번호와 막힌 까닭」
