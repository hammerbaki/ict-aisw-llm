# jobprep 요구사항 명세서 v1.2

| 항목 | 내용 |
|---|---|
| 대상 | 취업 준비 지원 서비스 `jobprep`(웹, 공고 요약 API, 취업 자료 질의응답) |
| 대상 사용자 | 전문대학 2학년 취업 준비생 |
| 판 | v1.2. v1.1(2026-11-14)에서 2장의 구현을 반영하였다. 「LLM 서비스 개발」의 공통 사례를 「AI에이전트 기획 및 개발」의 기준 저장소로 정리한 판이다 |
| 상태 표시 | **구현**: 코드와 자동 테스트가 있다. **구현(수동)**: 코드는 있으나 자동 테스트가 없고 화면에서 확인한다. **미구현**: 명세만 있고 코드와 테스트가 없다 |

## 1. 목적과 범위

이 명세서는 `jobprep`이 사용자에게 제공하는 기능과 운영 조건을 정한다. 범위는 채용 공고의 조회, 관심 공고의 저장, 공고 요약, 학과 취업 자료에 근거한 질의응답, 그리고 이 기능들을 운영하는 데 필요한 조건이다. 회원 가입, 지원서 제출, 외부 채용 사이트의 공고 수집은 범위에 넣지 않는다.

공고 30건(`data/jobs.json`)과 취업 자료 6편(`data/자료/`)은 모두 실습용 가상 자료이다.

## 2. 요구 문장의 형식

요구 문장은 EARS(Easy Approach to Requirements Syntax)의 문형을 따른다[R1]. 한 문장에는 요구 하나만 담고, 주어는 "시스템"으로 쓴다.

| 문형 | 영문 틀 | 이 명세서의 틀 |
|---|---|---|
| 상시 | The system shall ... | 시스템은 ~해야 한다 |
| 상태 | While ..., the system shall ... | ~인 동안, 시스템은 ~해야 한다 |
| 이벤트 | When ..., the system shall ... | ~하면, 시스템은 ~해야 한다 |
| 선택 | Where ..., the system shall ... | ~가 설정된 경우, 시스템은 ~해야 한다 |
| 원치 않는 상황 | If ..., then the system shall ... | 만약 ~이면, 시스템은 ~해야 한다 |

요구 ID는 `REQ-<영역>-<번호>`이다. 영역은 JOB(공고 조회), FAV(관심 공고), SUM(공고 요약), ASK(질의응답), OPS(운영)이다. 한 번 붙인 ID는 요구를 지워도 다른 요구에 다시 쓰지 않는다.

## 3. 요구사항

### 3.1 공고 조회 (REQ-JOB)

| ID | 문형 | 요구 | 인수 조건 | 상태 | 테스트 |
|---|---|---|---|---|---|
| REQ-JOB-01 | 상시 | 시스템은 공고 목록을 마감일이 이른 순으로 제공해야 한다. | `GET /api/jobs`가 30건을 마감일 오름차순으로 돌려준다. 목록 항목에는 본문(`description`)이 없다 | 구현 | `test_jobs.py::test_list_returns_all_jobs_without_description`, `test_list_is_sorted_by_deadline` |
| REQ-JOB-02 | 이벤트 | 사용자가 직무 분야를 고르면, 시스템은 그 분야의 공고만 보여야 한다. | `GET /api/jobs?field=<분야>`의 모든 항목의 `field`가 그 분야이다. 없는 분야이면 빈 목록이다 | 구현 | `test_list_filters_by_field`, `test_list_with_unknown_field_is_empty` |
| REQ-JOB-03 | 이벤트 | 사용자가 검색어를 넣으면, 시스템은 제목, 기업명, 본문 가운데 하나에 검색어가 들어간 공고만 보여야 한다. | `GET /api/jobs?q=<검색어>` | 구현 | `test_list_filters_by_keyword` |
| REQ-JOB-04 | 원치 않는 상황 | 만약 없는 공고 번호를 요청하면, 시스템은 404 상태 코드로 응답해야 한다. | `GET /api/jobs/999`가 404이다 | 구현 | `test_detail_of_missing_job_is_404` |
| REQ-JOB-05 | 상시 | 시스템은 공고마다 마감까지 남은 날 수를 함께 제공해야 한다. | 목록과 상세의 각 항목에 `days_left`(오늘 기준, 지난 공고는 음수)가 있다 | 구현 | `test_list_returns_all_jobs_without_description`, `test_days_left_uses_today` |
| REQ-JOB-06 | 이벤트 | 사용자가 마감 임박 조건으로 N일을 주면, 시스템은 오늘부터 N일 안에 마감되는 공고만 보여야 한다. | `GET /api/jobs?closing_within=7`은 `0 <= days_left <= 7`인 공고만 돌려준다. 마감이 지난 공고는 빠진다. N이 음수이거나 정수가 아니면 422이다. 다른 조건(`field`, `q`)과 함께 쓸 수 있다 | 구현 | `test_closing_within.py`의 4개 함수 |

### 3.2 관심 공고 (REQ-FAV)

| ID | 문형 | 요구 | 인수 조건 | 상태 | 테스트 |
|---|---|---|---|---|---|
| REQ-FAV-01 | 이벤트 | 사용자가 공고의 관심 표시를 누르면, 시스템은 그 공고를 브라우저에 관심 공고로 저장해야 한다. | 별표를 누른 뒤 페이지를 다시 열어도 별표가 채워져 있다. 서버에는 저장하지 않는다(localStorage) | 구현(수동) | 없음 |
| REQ-FAV-02 | 상태 | '관심 공고만 보기'가 켜져 있는 동안, 시스템은 관심 공고만 목록에 보여야 한다. | 체크 상자를 켜면 관심 공고만 남는다 | 구현(수동) | 없음 |

### 3.3 공고 요약 (REQ-SUM)

| ID | 문형 | 요구 | 인수 조건 | 상태 | 테스트 |
|---|---|---|---|---|---|
| REQ-SUM-01 | 이벤트 | 사용자가 공고 요약을 요청하면, 시스템은 핵심 업무, 자격 요건, 마감일, 주의점의 네 부분으로 요약해야 한다. | `POST /api/summary`(`{"text": 공고 본문}`)가 `duties`, `qualifications`, `deadline`, `cautions`를 돌려준다 | 구현 | `test_summary.py::test_summary_has_four_parts`, `test_summary_reads_deadline_and_duties` |
| REQ-SUM-02 | 상시 | 시스템은 요약의 각 목록을 문자열 5개 이내로, 마감일을 YYYY-MM-DD 또는 null로 제공해야 한다. | 형식이 틀린 응답은 받아들이지 않는다. 6개 이상이면 앞의 5개만 남긴다 | 구현 | `test_validate_summary_rejects_wrong_shape`, `test_validate_summary_keeps_at_most_five_items` |
| REQ-SUM-03 | 상시 | 시스템은 요약 결과에 사용한 프롬프트 판본과 모델 이름을 함께 제공해야 한다. | 응답에 `prompt_version`, `model`이 있다 | 구현 | `test_summary_has_four_parts` |
| REQ-SUM-04 | 원치 않는 상황 | 만약 LLM을 부를 수 없으면 503으로, LLM의 응답을 요약 구조로 읽을 수 없으면 502로 응답해야 한다. | 응답 본문의 `detail`에 까닭이 있다 | 구현 | `test_summary_when_llm_fails_is_503`, `test_summary_when_reply_is_not_json_is_502` |
| REQ-SUM-05 | 원치 않는 상황 | 만약 요약할 본문이 비어 있거나 4,000자를 넘으면, 시스템은 LLM을 부르지 않고 422로 응답해야 한다. | 빈 문자열, 공백만 있는 문자열, 4,001자 문자열은 422이다. 4,000자는 받아들인다 | 구현 | `test_input_limits.py::test_summary_rejects_empty_or_too_long_text`, `test_summary_accepts_text_of_4000_chars` |

### 3.4 취업 자료 질의응답 (REQ-ASK)

| ID | 문형 | 요구 | 인수 조건 | 상태 | 테스트 |
|---|---|---|---|---|---|
| REQ-ASK-01 | 이벤트 | 사용자가 질문하면, 시스템은 취업 자료에서 찾은 근거만으로 답하고 근거 번호를 [1]처럼 밝혀야 한다. | `POST /api/ask`(`{"question": 질문}`)의 `answer`에 근거 번호가 있다 | 구현 | `test_ask.py::test_answer_cites_source` |
| REQ-ASK-02 | 상시 | 시스템은 답이 인용한 근거마다 파일 이름, 문서와 절의 제목, 유사도를 제공해야 한다. | `sources`의 항목에 `no`, `source`, `title`, `score`가 있다 | 구현 | `test_answer_cites_source` |
| REQ-ASK-03 | 원치 않는 상황 | 만약 질문과 가장 가까운 근거의 유사도가 기준값보다 낮으면, 시스템은 LLM을 부르지 않고 "자료에 없습니다."로 답해야 한다. | `answer`가 "자료에 없습니다."이고 `sources`가 비어 있다. LLM이 같은 답을 내도 `sources`는 비어 있다 | 구현 | `test_question_outside_material_says_not_found`, `test_not_found_answer_from_llm_has_no_sources` |
| REQ-ASK-04 | 원치 않는 상황 | 만약 LLM을 부를 수 없으면, 시스템은 503으로 응답해야 한다. | | 구현 | `test_ask_when_llm_fails_is_503` |
| REQ-ASK-05 | 상시 | 시스템의 검색은 평가 문항 10개에서 상위 3개 재현율 80% 이상을 유지해야 한다. | `rag/평가문항.csv`, 대체 임베딩 기준. `python -m rag.index eval rag/평가문항.csv`로도 잰다 | 구현 | `test_rag.py::test_recall_at_3_is_at_least_80_percent` |
| REQ-ASK-06 | 원치 않는 상황 | 만약 질문이 비어 있거나 500자를 넘으면, 시스템은 검색과 LLM 호출 없이 422로 응답해야 한다. | 빈 문자열, 공백만 있는 문자열, 501자 문자열은 422이다. 500자는 받아들인다 | 구현 | `test_input_limits.py::test_ask_rejects_empty_or_too_long_question`, `test_ask_accepts_question_of_500_chars` |

| ID | 문형 | 요구 | 인수 조건 | 상태 | 테스트 |
|---|---|---|---|---|---|
| REQ-OPS-01 | 상시 | 시스템은 서버의 상태를 확인하는 경로를 제공해야 한다. | `GET /api/health`가 `status`, `llm_fake`, `jobs`를 돌려준다. 키와 같은 설정값은 내보내지 않는다 | 구현 | `test_jobs.py::test_health_reports_ok_and_fake_mode` |
| REQ-OPS-02 | 선택 | 모의 모드(`LLM_FAKE=1`)가 설정된 경우, 시스템은 LLM API를 부르지 않고 같은 입력에 언제나 같은 응답을 내야 한다. | | 구현 | `test_llm.py::test_fake_summary_is_deterministic`, `test_fake_answer_without_evidence_is_not_found` |
| REQ-OPS-03 | 상시 | 시스템은 모델 이름과 프롬프트 판본을 코드가 아니라 환경 변수(`LLM_MODEL`, `PROMPT_SUMMARY`, `PROMPT_ASK`)로 받아야 한다. | | 구현 | `test_prompt_version_can_be_changed`, `test_real_mode_without_model_raises` |
| REQ-OPS-04 | 원치 않는 상황 | 만약 실제 모드에서 API 키가 없으면, 시스템은 API를 부르기 전에 그 사실을 알리는 오류를 내야 한다. | | 구현 | `test_real_mode_without_key_raises_before_calling` |
| REQ-OPS-05 | 상시 | 시스템은 API 키를 서버의 환경 변수에만 두고, 브라우저 코드와 저장소에 넣지 않아야 한다. | `web/`에 키가 없다. `.env`는 `.gitignore`에 있다 | 구현(수동) | 없음 |
| REQ-OPS-06 | 상시 | 시스템은 요청마다 방법, 경로, 상태 코드, 처리 시간을 한 줄로 기록해야 한다. | 형식은 `logs/README.md`를 따른다 | 구현(수동) | 없음 |

## 4. 2장에서 구현한 요구

다음 세 요구는 v1.1에서 미구현이었고, 2장(테스트 주도 개발)에서 테스트를 먼저 쓰고 구현하였다.

| ID | 요약 | 고친 곳 |
|---|---|---|
| REQ-JOB-06 | 마감 임박 필터 `closing_within` | `api/main.py`의 `list_jobs`, `api/jobs.py`의 `list_jobs` |
| REQ-SUM-05 | 요약 입력의 길이 제한과 422 | `api/main.py`의 `check_length`, `post_summary` |
| REQ-ASK-06 | 질문의 길이 제한과 422 | `api/main.py`의 `check_length`, `post_ask` |
