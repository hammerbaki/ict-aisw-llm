# 장애 보고서 서식

`jobprep` 운영팀이 쓰는 장애 보고서의 서식이다. 보고서 하나가 장애 하나를 다룬다. 저장 위치는 `docs/운영/장애보고/YYYY-MM-DD.md`이고, 같은 날 장애가 둘이면 `YYYY-MM-DD-2.md`로 나눈다. `scripts/check_report.py`가 아래 규칙 가운데 기계로 볼 수 있는 것을 검사한다. `{{ }}`로 감싼 자리는 모두 채워야 한다.

```markdown
# 장애 보고서: {{YYYY-MM-DD}} {{한 줄 제목: 기능 + 증상}}

- 심각도: {{SEV1 | SEV2 | SEV3}} (references/심각도기준.md의 어느 조건에 해당하는지 한 구절)
- 작성: incident-report 스킬 초안, 검토자 {{이름}}
- 상태: 초안

## 1. 요약

{{두세 문장: 언제, 어느 기능이, 어떻게 실패했고, 지금은 어떤 상태인가}}

## 2. 영향

| 항목 | 값 |
|---|---|
| 영향받은 기능 | {{경로와 기능 이름}} |
| 시간대 | {{시작 ~ 끝, 지속 시간}} |
| 실패 또는 지연 요청 | {{건수, 상태 코드}} |
| 그날 전체 요청 | {{건수}} |

## 3. 경과

| 시각 | 사건 | 근거 |
|---|---|---|
| {{HH:MM:SS}} | {{무슨 일이 기록되었는가}} | {{logs/파일.log}} |

## 4. 원인

{{기록이 보여 주는 직접 원인. 기록만으로 알 수 없는 근본 원인은 "확인 필요"와 확인할 방법을 적는다}}

## 5. 조치와 재발 방지

- {{이미 한 조치 또는 "기록에 조치 기록 없음"}}
- {{재발 방지 제안 1~3개. 담당 장(예: 8장 재시도 상한, 12장 관측)이 있으면 함께 적는다}}

## 6. 근거 기록

- {{logs/파일.log에서 어떤 조건으로 찾았는가, 예: 2027-09-08 14시대 status=503}}
- 요약 스크립트: scripts/log_summary.py --date {{YYYY-MM-DD}}
```

## 쓰는 규칙

1. 건수와 시각은 `log_summary.py`의 출력에서 옮긴다. 기록을 눈으로 세어 쓰지 않는다.
2. 경과 표의 행마다 근거 칸에 기록 파일 경로를 적는다. 행은 시각 순서이고 최소 2행이다(시작과 끝).
3. 원인 절은 기록에 있는 사실(오류 이름, 상태 코드)과 추정을 나누어 쓴다. 추정에는 "추정"을, 기록으로 알 수 없는 것에는 "확인 필요"를 붙인다.
4. 사람 이름, 사용자 질문 원문, 키 값은 보고서에 쓰지 않는다. 기록에 없는 정보이기도 하다.
