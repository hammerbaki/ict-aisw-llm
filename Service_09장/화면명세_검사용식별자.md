## 검사용 약속 (9장에서 추가)

> 이 절을 `jobprep/docs/설계/화면명세.md`(8장, v3)의 맨 뒤에 붙인다. 자동 검사(`web/check/`)는 아래 식별자로 화면의 요소를 찾는다. 구현은 이 식별자를 바꾸지 않는다. 식별자를 바꾸어야 하면 이 표와 검사를 함께 고친다.

### 화면과 구현 파일

| 화면 | 8장 프로토타입 | 9장 구현 |
|---|---|---|
| SCR-01 공고 목록 | `prototype/index.html` | `web/index.html` |
| SCR-02 공고 상세 | `prototype/job.html` | `web/detail.html` |
| SCR-03 지원 일정 | `prototype/schedule.html` | `web/schedule.html`(아래쪽 목록) |
| SCR-04 지원 일정 등록 | `prototype/schedule-new.html` | `web/schedule.html`(위쪽 양식) |
| SCR-07 관심 공고 | (8장 범위 밖) | `web/saved.html` |

### 파일과 경로

- 화면 파일은 `web/index.html`, `web/detail.html`, `web/saved.html`, `web/schedule.html`이다.
- 공고 자료는 `web/data/jobs.json`이고, 화면은 이를 상대 경로 `data/jobs.json`으로 읽는다. 자료의 「기업」(`company`)이 명세의 「모집기관」이다.
- 모든 경로는 상대 경로로 쓴다. `/`로 시작하는 경로는 쓰지 않는다(프로젝트 사이트는 `…github.io/저장소이름/` 아래에 열린다).
- 외부 주소(CDN, 글꼴, 분석 도구)를 부르지 않는다.

### 정렬과 기준일

- 정렬(REQ-002): 접수 마감일이 가까운 순서. 마감일이 같으면 공고 번호 순. 마감일이 없는(`null`) 상시 공고는 맨 뒤.
- 기준일(REQ-003): 모든 화면은 주소에 `?today=YYYY-MM-DD`가 있으면 그 날을 오늘로 본다. 화면 사이를 옮겨 갈 때도 이 값을 이어 붙인다. 없으면 브라우저의 오늘 날짜를 쓴다.
- 마감 표시(REQ-003): `.deadline-badge` 요소 하나. 0~3일 남으면 「마감 임박 D-N」(0일은 「마감 임박 D-day」), 지난 공고는 「마감」. 표시할 것이 없으면 요소를 만들지 않는다.

### 브라우저 저장소

| 키 | 값 | 요구 |
|---|---|---|
| `jobprep:saved` | 관심 공고 번호의 JSON 배열. 예: `["JOB-003","JOB-017"]` | REQ-008, REQ-009, REQ-038 |
| `jobprep:schedule` | 지원 일정의 JSON 배열. 항목은 `{"id","jobId","stage","date","memo"}` | REQ-009, REQ-010, REQ-032 |

키 앞의 `jobprep:`는 같은 출처(`https://아이디.github.io`)를 쓰는 다른 저장소의 사이트와 키가 겹치지 않게 하기 위한 것이다.

| SCR-02 | `#job-detail` | 공고 상세 영역(없는 공고일 때는 숨김) |

| SCR-04 | `#schedule-error` | 입력 오류 문구 |
| SCR-03 | `#schedule-list`, `.schedule-item[data-date]`, `.delete-schedule` | 일정 목록, 항목(`data-date`에 날짜), 삭제 버튼(누르면 확인 창) |
| SCR-03 | `#schedule-empty` | 빈 상태 |
