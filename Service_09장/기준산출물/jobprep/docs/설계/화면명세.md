# 화면 명세: 취업 준비 지원 서비스(jobprep)

- 판: v3.0 (8장 정답 예시. 학생의 결과가 이와 같을 필요는 없다). 명세서 v3.0과 같은 판 번호를 쓰고 태그 `spec-v3`로 함께 묶는다. 이 화면 명세에서 정한 요구는 명세서 v3의 REQ-028~039이다
- 입력: `docs/요구사항명세서.md`(v2, 화면 목록), `docs/설계/정보구조.md`, `docs/설계/사용자흐름.md`, `docs/설계/디자인토큰.md`(v1.0)
- 범위: 핵심 화면 4개(SCR-01~04). SCR-05, 06은 10~11장, SCR-07(관심 공고)은 9장, SCR-08(설정)은 이후 장에서 쓴다.
- 이 파일은 기능의 기준이다. 배치는 각 화면의 와이어프레임이 기준이다. 둘이 어긋나면 구현자는 임의로 정하지 않고 묻는다.

## 0. 모든 화면에 공통

| 항목 | 내용 |
|---|---|
| 머리 | 서비스 이름 「jobprep 취업 준비」, 전역 내비게이션(공고, 지원 관리, 자기소개서, 자료 묻기. 정보구조.md의 순서와 레이블), 오른쪽 위의 유틸리티 링크 「설정」. 현재 화면은 `aria-current="page"`. SCR-03과 SCR-04는 「지원 관리」가 현재 항목이다. 아직 없는 화면(자기소개서, 자료 묻기, 설정)은 비활성으로 보이고 초점을 받지 않는다 |
| 지역 내비게이션 | 정보구조.md의 「지원 관리」 안의 탭(지원 일정, 관심 공고)은 SCR-07을 만드는 9장에서 더한다 |
| 본문 바로가기 | 첫 번째 초점 위치에 「본문 바로가기」 링크. 초점을 받을 때만 보인다 |
| 제목 | 화면마다 `h1` 하나. 제목 단계를 건너뛰지 않는다 |
| 문구의 말투 | 화면 문구는 해요체. 버튼은 동사로 끝낸다(「일정 저장」, 「요약 만들기」) |
| 중단점 | 기본(모바일) 1열, 40rem(640px) 이상 2열, 64rem(1024px) 이상 3열 |
| 초점 표시 | `color-focus` 3px 테두리, 요소에서 2px 띄움 |
| 누름 영역 | 버튼, 내비게이션, 홀로 놓인 링크는 높이 44px(`size-target-min`) 이상 |
| 적용 요구 | REQ-033(키보드), REQ-034(대비), REQ-035(320px), REQ-036(레이블) |

## SCR-01. 공고 목록

### 1) 개요

| 항목 | 내용 |
|---|---|
| 화면 ID | SCR-01 |
| 목적 | 사용자가 조건에 맞는 공고를 마감일이 가까운 순으로 훑어보고 하나를 고른다 |
| 관련 요구 | REQ-001, REQ-002, REQ-003, REQ-004, REQ-005, REQ-006, REQ-007, REQ-028, REQ-029 |
| 들어오는 길 | 서비스 첫 화면. 전역 내비게이션 「공고」 |
| 나가는 길 | 공고 제목 → SCR-02 |
| 사용자 흐름 | FLOW-01의 1~2단계 |

### 4) 상태

| 상태 | 언제 | 화면에 보이는 것 | 문구 |
|---|---|---|---|
| 기본 | 공고가 1건 이상 | 결과 수와 카드 목록 | 「공고 N건」 |
| 로딩 | 공고를 불러오는 동안 | 카드 자리에 회색 상자 3개, 영역에 `aria-busy="true"` | 「공고를 불러오는 중이에요」 |
| 빈 상태 | 조건에 맞는 공고가 0건 | 안내 상자: 제목, 바꾸는 방법, 「조건 모두 지우기」 버튼 (REQ-007) | 「조건에 맞는 공고가 없어요」, 「검색어를 줄이거나 상태·지역·직무를 「전체」로 바꿔 보세요.」 |
| 오류 | 공고 자료를 읽지 못함 | 오류 상자(`role="alert"`)와 「다시 불러오기」. 빈 목록으로 두지 않는다 (REQ-004) | 「공고 자료를 불러오지 못했어요. 인터넷 연결을 확인한 뒤 다시 불러와 주세요.」 |

### 5) 상호작용

| 사용자 동작 | 시스템 반응 | 관련 요구 |
|---|---|---|
| 검색어를 입력한다 | 목록을 즉시 거르고 결과 수를 갱신한다. 화면은 옮기지 않는다. 검색 단추를 따로 두지 않는다(입력할 때마다 거르는 것이 REQ-006의 「검색을 누르면」을 대신한다) | REQ-006, REQ-029 |
| 상태를 바꾼다 | 위와 같다 | REQ-005, REQ-029 |
| 지역이나 직무 분야를 바꾼다 | 위와 같다 | REQ-028, REQ-029 |
| 「조건 모두 지우기」를 누른다 | 조건을 비우고 전체 목록을 보이며, 초점을 검색어 칸으로 옮긴다 | REQ-007 |
| 공고 제목을 누른다 | SCR-02로 간다 | REQ-030 |

### 6) 접근성 메모

| 항목 | 내용 | WCAG |
|---|---|---|
| 초점 순서 | 본문 바로가기 → 서비스 이름 → 내비게이션 → 검색어 → 상태 → 지역 → 직무 분야 → 카드 제목들 | 2.4.3 |
| 상태 알림 | 결과 수 문장은 `role="status"`. 필터를 바꿔도 초점은 그대로 두고 수만 읽힌다 | 4.1.3 |
| 입력 중 화면 전환 금지 | 선택을 바꿔도 다른 화면으로 가지 않는다 | 3.2.2 |
| 마감 임박 | 색 상자와 함께 「마감 임박 D-2」 글자로 알린다 | 1.4.1 |
| 검색 영역 | `role="search"`와 `aria-label`로 랜드마크를 둔다 | 1.3.1 |

### 7) 열린 질문

- 공고가 수백 건이 되면 쪽 나누기와 「더 보기」 중 무엇을 쓰는가 → 9장에서 실제 데이터 규모를 보고 정한다.
- REQ-008의 관심 표시를 공고 카드에도 둘 것인가 → 이 판은 두지 않는다. 카드에 단추가 하나 더 생기면 제목, 마감의 위계가 흐려진다. 관심 표시는 SCR-02와 SCR-07에 두고, 13장 사용성 평가에서 다시 본다(명세서 v3의 화면 목록에 반영).

## SCR-02. 공고 상세

### 1) 개요

| 항목 | 내용 |
|---|---|
| 화면 ID | SCR-02 |
| 목적 | 사용자가 공고의 핵심 조건을 확인하고, 필요하면 요약을 읽고 원문과 대조한 뒤 관심 공고로 저장하거나 지원 일정에 추가한다 |
| 관련 요구 | REQ-008, REQ-010, REQ-013, REQ-014, REQ-015, REQ-016, REQ-024, REQ-025, REQ-030, REQ-037, REQ-038 |
| 들어오는 길 | SCR-01의 공고 제목, SCR-03의 일정 제목 |
| 나가는 길 | 「지원 일정에 추가」 → SCR-04(값이 채워진 채로), 「공고 목록으로」 → SCR-01 |
| 사용자 흐름 | FLOW-01의 3~4단계(공고 상세, 요약 요청, 지원 여부 판단, 관심 표시) |

### 4) 상태

| 상태 | 언제 | 화면에 보이는 것 | 문구 |
|---|---|---|---|
| 기본 | 처음 열었을 때 | 요약 영역에 설명과 「요약 만들기」 | 「자격 요건, 근무 조건, 제출 서류, 접수 마감일의 네 항목으로 나누고, 항목마다 근거가 된 원문 문장을 달아요.」 |
| 생성 중 | 요청 뒤 응답 전 (REQ-016) | 버튼에 돌아가는 표시, `aria-busy`, `aria-disabled` | 「요약을 만드는 중이에요. 보통 10초 안에 끝나요.」 |
| 완료 | 응답 성공 | AI 고지, 네 항목, 근거 문장과 링크, 버튼 「다시 만들기」 | 「AI가 만든 요약이에요. 마감일과 자격 요건은 근거 문장과 원문 문단을 눌러 확인해 주세요.」 |
| 오류 | 응답 실패, 시간 초과, 형식 오류 (REQ-024) | 오류 상자, 버튼 「다시 시도」. 원문은 그대로 | 「요약을 만들지 못했어요. 잠시 뒤 「다시 시도」를 눌러 주세요. 원문은 그대로 읽을 수 있어요.」 |
| 한도 | 사용 한도를 넘음 (REQ-025) | 요청을 보내지 않고 안내 상자. 원문은 그대로 | 「오늘 쓸 수 있는 요약 횟수를 다 썼어요. 내일 0시부터 다시 만들 수 있어요. 원문은 그대로 읽을 수 있어요.」 |
| 없는 공고 | 주소의 공고 번호가 자료에 없음 (REQ-037) | 공고 정보와 요약 영역을 숨기고 안내 상자와 목록 링크 | 「찾을 수 없는 공고예요」, 「주소의 공고 번호를 확인하거나 공고 목록에서 다시 골라 주세요.」 |

### 6) 접근성 메모

### 7) 열린 질문

- 요약 한 번에 드는 비용과 하루 요청 한도를 사용자에게 보일 것인가 → 10장에서 비용을 잰 뒤 정한다. 응답을 몇 초 기다린 뒤 실패로 볼지는 Q-05로 10장이 정한다.
- 요약이 틀렸다고 알리는 「의견 보내기」를 둘 것인가 → 13장 사용성 평가 뒤 정한다.
