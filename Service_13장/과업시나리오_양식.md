# 과업 시나리오

> 이 파일을 복사해 `reviews/ch13/「내 아이디」/jobprep/docs/평가/과업시나리오.md`로 저장하고 채운다. 과업은 3개다.
> 과업 카드(참가자에게 보여 주는 부분)에는 화면의 메뉴 이름과 버튼 이름을 쓰지 않는다.

## 1. 테스트의 목적과 질문

| 항목 | 내용 |
|---|---|
| 목적 | 「예: 12장에서 병합한 잡프렙의 핵심 흐름 세 가지에서 사용자가 막히는 곳을 찾는다(형성 평가)」 |
| 알고 싶은 것 1 | 「예: 사용자가 마감이 가까운 공고를 찾아 지원 일정에 넣을 수 있는가」 |
| 알고 싶은 것 2 | 「예: AI 요약을 보고 그 내용이 공고의 어디에서 나왔는지 확인할 수 있는가」 |
| 알고 싶은 것 3 | 「예: 학과 취업 자료에 없는 질문을 했을 때 사용자가 다음에 할 일을 아는가」 |
| 참가자 조건 | 이 프로덕트를 만들지도, 휴리스틱 평가를 하지도 않은 사람. 다른 팀의 수강생 |

## 2. 과업

과업마다 참가자에게 읽어 줄 카드, 시작 상태, 성공 기준, 제한 시간을 정한다.

### T1

- 과업 카드 (참가자에게 보여 준다)

  > 「예: 일주일 안에 마감하는 서울 지역의 백엔드 신입 공고 하나를 골라, 나중에 잊지 않도록 지원할 목록에 넣어 두세요.」

- 시작 상태: 「첫 화면. 지원 일정은 비어 있음(브라우저 저장소를 비움)」
- 제한 시간: 「4분」
- 성공 기준

| 수준 | 기준 |
|---|---|
| 완전성공 | 「조건(7일 안, 서울, 백엔드 신입)에 맞는 공고가 지원 일정에 한 번 들어감」 |
| 사소한문제 | 「맞는 공고가 들어갔으나 같은 공고가 두 번 들어감」 |
| 큰문제 | 「조건에 맞지 않는 공고가 들어감」 |
| 실패 | 「제한 시간 안에 넣지 못함, 또는 포기」 |
