# 요구사항 명세서: 잡프렙 (13장 평가용 견본)

- 판: v7.1 (12장 비교 구현 뒤 병합본을 줄인 견본)
- 대상 사용자: 전문대학 2학년 취업 준비생 (페르소나 `ch05/페르소나.md`의 PS-1 서지후, PS-2 임하람)
- 이 견본은 13장 실습에 필요한 요구만 남긴 발췌본이다. 6~12장의 실제 명세서는 더 길다.
- 요구 ID는 이 견본 안에서 새로 매겼다(REQ-001~013). 7장 정본 명세서의 같은 번호와 뜻이 대응하지 않는다. 13장에서 더하는 요구는 13장의 구간(REQ-100~119)에서 쓴다.

## 1. 기능 요구

| ID | 요구 (EARS 문형) | 화면 | 출처 |
|---|---|---|---|
| REQ-001 | 시스템은 채용 공고를 마감일이 가까운 순서로 목록에 보여야 한다. | SCR-01 | 문제정의 P-01 |
| REQ-002 | 사용자가 키워드를 입력하고 검색을 실행하면, 시스템은 회사명, 직무명, 본문에 키워드가 든 공고만 보여야 한다. | SCR-01 | P-01 |
| REQ-003 | 사용자가 지역을 골라 적용하면, 시스템은 그 지역의 공고만 보여야 한다. | SCR-01 | P-01 |
| REQ-004 | 시스템은 공고마다 회사명, 직무명, 지역, 마감일, 남은 날 수를 보여야 한다. | SCR-01 | P-01 |
| REQ-005 | 사용자가 공고를 지원 일정에 저장하면, 시스템은 그 공고를 브라우저 저장소에 저장하고 지원 일정 목록에 보여야 한다. | SCR-01, SCR-03 | P-01 |
| REQ-006 | 사용자가 지원 일정을 직접 입력하면, 시스템은 회사, 마감일, 메모를 저장해야 한다. | SCR-03 | P-01 |
| REQ-007 | 사용자가 공고 요약을 요청하면, 시스템은 10초 안에 자격, 우대 사항, 전형을 항목으로 나누어 보여야 한다. | SCR-01 | P-02 |
| REQ-008 | 사용자가 취업 자료에 대해 질문하면, 시스템은 학과 취업 자료를 근거로 답해야 한다. | SCR-06 | P-02 |
| REQ-009 | 만약 질문에 대한 근거가 취업 자료에 없으면, 시스템은 자료에 없다고 답해야 한다. | SCR-06 | 11장 |
| REQ-010 | 사용자가 지원 일정의 항목을 지우면, 시스템은 그 항목을 목록과 저장소에서 지워야 한다. | SCR-03 | P-01 |

## 2. 비기능 요구 (기능 요구와 같은 형식의 ID를 쓴다)

| ID | 요구 | 출처 |
|---|---|---|
| REQ-011 | 시스템은 API 키를 브라우저 코드와 저장소에 두지 않아야 한다. | 10장 |
| REQ-012 | 시스템은 휴대폰 화면 너비(360px)에서도 가로 스크롤 없이 읽혀야 한다. | 8장 |
| REQ-013 | 시스템의 본문 글자는 배경과의 명암비 4.5:1 이상이어야 한다. | 8장 (WCAG 2.2 1.4.3) |

## 3. 명세가 정하지 않은 것 (12장에서 찾은 빈틈, 아직 열려 있음)

- 요약을 만드는 동안 화면에 무엇을 보일지
- 요약이 공고의 어느 문장에서 나왔는지 보일지
- 지운 지원 일정을 되살릴 수 있게 할지
