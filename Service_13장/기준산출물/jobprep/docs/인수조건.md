# 인수 조건: 공고 모아보기 웹 (9장 기준 산출물 견본, 명세 v4)

> 9장 산출물이 없는 학습자를 위한 견본이다. 10장 이후에 더한 행(예: `AC-013-2`)은 들어 있지 않다. 자기 산출물이 있으면 그것을 쓴다.
> 번호는 `AC-<요구 번호 세 자리>-<순번>`이다. 명세서 6절의 수용 기준 `AC-NNN-1`을 이 장의 공고 자료로 구체화한 행은 같은 번호를 쓰고, 이 장에서 더한 행은 다음 순번을 쓴다.

## 기준

- 명세 판: v4 (8장 v3 + CR-01, 태그 `spec-v4`), 화면 명세: v3, 검사용 약속 포함
- 검사한 날: 2026-11-14, 검사 환경: Windows 11, Playwright 1.64.0, Chromium(headless, chromium_headless_shell-1248), 기본 창 1280×720과 320×640

## 학생 표에서 자주 보이는 문제와 판정

| 문제 | 예 | 판정 |
|---|---|---|
| Then이 관찰할 수 없는 말이다 | "검색이 잘 된다", "빠르게 보인다" | 미통과. 무엇을 보면 되는지(카드 수, 문구)로 고치게 한다 |
| Given이 없다 | "검색어를 넣으면 결과가 나온다" | 미통과. 몇 건이 있는 상태에서 시작하는지 적게 한다 |
| 구현 방법을 적었다 | "filter 함수가 배열을 거른다" | 미통과. 사용자가 보는 결과로 쓰게 한다 |
| When에 행동이 둘 이상 | "검색하고 분야를 고르고 지역을 고른다" | 통과로 보되, 하나씩 나누는 편이 실패 원인을 찾기 쉽다고 알린다 |
| 요구와 연결이 없다 | 요구 칸이 비었다 | 미통과 |
| 번호가 두 자리다 | `AC-06-1`, `REQ-06` | 미통과. 명세의 세 자리 번호(`AC-007-1`, `REQ-007`)로 고치게 한다 |
| 구현하지 않는 요구에 인수 조건을 두었다 | REQ-005(상태 선택)에 "결과: 실패" | 통과로 보되, 표에서 빼고 작업목록의 「이 판에서 구현하지 않는 요구」로 옮기게 한다 |
| AC-040-1에서 마감일 순으로 저장했다 | "이른 공고부터 저장하면 이른 공고가 먼저 보인다" | 미통과. 저장한 순서대로 보이는 구현도 통과하므로 아무것도 확인하지 않는다. 역순으로 저장하게 한다 |
