# 사용성 테스트 결과

> 이 파일을 복사해 `reviews/ch13/「내 아이디」/jobprep/docs/평가/사용성테스트.md`로 저장한다. 프로덕트 주인이 쓴다.
> 표의 숫자는 `도구/aggregate.py`의 출력을 붙인다. 손으로 다시 계산하지 않는다.

## 1. 테스트 개요

| 항목 | 내용 |
|---|---|
| 대상 | reviews/ch13/「내 아이디」/jobprep, 커밋 「7자리」 |
| 종류 | 과업 기반, 사고 발화, 대면, 형성 평가 |
| 참가자 | 「P1, P2, P3」 (다른 팀 수강생, 이 프로덕트를 만들거나 평가하지 않음) |
| 진행자 / 기록자 | 「아이디」 / 「아이디」 |
| 과업 | `과업시나리오.md`의 T1~T3 |
| 환경 | 「브라우저, 화면 너비, LLM 모드(모의/실제)」 |
| 원기록 | `관찰/P1.md`, `관찰/P2.md`, `관찰/P3.md`, `자료/과업기록.csv` |

## 2. 과업 결과

(아래 명령의 출력을 붙인다)

```bash
python ~/kits/Service_13장/도구/aggregate.py tasks 자료/과업기록.csv --md
```

「출력 표」

- 성공 수준은 참가자 수와 함께 읽는다(예: "3명 중 2명이 완전성공"). 참가자가 5명 미만이므로 비율을 일반화하지 않는다.
- 소요 시간은 사고 발화 때문에 실제 사용보다 길다. 개선 전후를 견주는 데만 쓴다.

관찰 기록에서 뽑은 문제다. 문제마다 근거가 된 원기록의 위치(파일과 시각)를 적는다.

| T-01 | 「」 | 「P1, P3」 | 「관찰/P1.md 02:10, 관찰/P3.md 01:45」 | 「H1」 | 「H-01」 |
| T-02 | | | | | |
| T-03 | | | | | |

관찰 기록의 정리에 AI를 썼다면 무엇을 맡겼는지, 원기록과 대조해 고친 것을 적는다.

|---|---|---|

## 7. 통합 문제 목록과 우선순위

휴리스틱 평가(H-번호)와 사용성 테스트(T-번호)의 문제를 합친 `자료/문제목록.csv`를 집계한 결과를 붙인다. 같은 문제는 한 줄로 합치고 출처를 `둘다`로 적는다.

```bash
python ~/kits/Service_13장/도구/aggregate.py problems 자료/문제목록.csv --md
```

「출력」

- 이슈로 등록할 상위 세 문제: 「U-01 → 이슈 #」, 「U-02 → 이슈 #」, 「U-03 → 이슈 #」
- 규칙과 다르게 순서를 정한 것이 있으면 그 까닭: 「」
