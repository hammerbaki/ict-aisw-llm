# Service_06장: 리버스 엔지니어링과 명세 주도 개발 (실습 키트)

「LLM 서비스 개발」 6장(학사 7주차)의 재료다. 강의안 `Service_06장_학생용.md`의 0절에서 받아 쓴다. 실습은 각자의 PC(Windows는 Git Bash, macOS는 기본 터미널)에서 한다.

## 받는 법

키트 저장소를 1주차에 `~/kits-repo`로 클론해 두었다는 전제다(부록 A-12-2). 장마다 다음을 실행한다(부록 A-12-3).

```bash
git -C ~/kits-repo pull
mkdir -p ~/kits
cp -rn ~/kits-repo/Service_06장 ~/kits/
```

`~/kits`가 없을 때 `mkdir -p` 없이 복사하면 `~/kits` 자체가 키트 폴더가 된다. 먼저 폴더를 만든다.

## 쓰는 순서

명령은 가상 환경을 켠 터미널에서 실행한다(Windows `source ~/llm-service-lab/.venv/Scripts/activate`, macOS `source ~/llm-service-lab/.venv/bin/activate`. 부록 A-13). Windows에서는 `export PYTHONUTF8=1`도 한 번 해 둔다.

1. 0-2: `cd ~/kits/Service_06장` 뒤 `python -m pip install -q -r requirements.txt`, `python -m pytest -q`로 검사기가 도는지 본다. 학생 키트(`교수/` 없음)는 `33 passed, 1 skipped`, 교수용 사본은 `41 passed`가 정상이다.
2. 0-3: `~/llm-service-lab/ch04`, `ch05`가 없으면 `기준산출물/`을 복사한다(`cp -rn`은 있는 파일을 덮어쓰지 않는다).
3. 4-7(따라 하기 1): `연습/교정연습_원문.md`를 `ch06/연습/교정연습.md`로 복사해 세 문장을 고치고 검사기를 다시 돌린다.
4. 10-3~10-7(핵심 실습 앞부분): `복원/`의 자료와 양식을 `ch06/복원/`으로 복사하고 명세 복원 → 재구현 → 비교 → 빈틈 되돌리기를 한다.
5. 10-8~10-13(핵심 실습 뒷부분): `도구/ears_check.py`를 `jobprep/tools/`로, `양식/`의 세 파일을 `jobprep/` 아래로 복사해 명세서 v1, 추적표, `CLAUDE.md`를 쓰고, 복원에서 찾은 빈틈을 jobprep 명세에서 막은 뒤 태그 `spec-v1`을 단다.

## 검사기 사용법

```bash
python tools/ears_check.py docs/요구사항명세서.md --trace docs/추적표.md --problems ../ch05/문제정의.md
python ~/kits/Service_06장/도구/ears_check.py ch06/복원/복원명세.md --id "REQ-\d{2}"
```

- 종료 코드: 오류 0건이면 0, 오류가 있으면 1(`--strict`이면 경고도 오류로 센다), 파일이 없으면 2.
- 주체 이름이 「시스템」이 아니면 `--system 이름`을 준다(여러 번 줄 수 있다).
- 요구 ID의 기본 꼴은 `REQ-001`(두세 자리)이다. 다른 꼴은 `--id`에 정규식으로 준다.
- Windows에서 Git for Windows로 키트 저장소를 클론하면 텍스트 파일이 CRLF로 꺼내질 수 있다. 검사기와 테스트는 CRLF 파일에서도 같은 결과를 낸다(2026-11-17 확인).
