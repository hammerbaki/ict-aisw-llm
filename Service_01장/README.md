# 1장 키트: 생성형 AI 기반 서비스 개발의 개요

「LLM 서비스 개발」 1장(학사 2주차)의 실습 재료이다. 강의안은 `Service_01장_학생용.md`이다.

## 받는 법

키트는 수업용 조직의 키트 저장소에 있다. 1주차에 그 저장소를 `~/kits-repo`로 클론해 두었다고 전제한다(부록 A-12-2). 모든 장과 같이 키트를 저장소 밖의 `~/kits/`로 받은 뒤(부록 A-12-3), 1장은 그 내용물을 작업 폴더 `~/llm-service-lab/ch01/`에 그대로 복사한다.

```bash
git -C ~/kits-repo pull
mkdir -p ~/kits ~/llm-service-lab/ch01
cp -rn ~/kits-repo/Service_01장 ~/kits/
cp -rn ~/kits/Service_01장/. ~/llm-service-lab/ch01/
```

`-n`은 이미 있는 파일을 덮어쓰지 않는다. 다시 받아도 학습자가 고친 파일은 그대로 남는다. `~/kits/Service_01장/`는 키트의 원본 사본으로 두고 고치지 않는다.

1장 시점에는 `~/llm-service-lab/`이 아직 Git 저장소가 아니다. 2장에서 이 폴더를 저장소로 만들고 `ch01/`을 첫 커밋에 넣는다.

## 들어 있는 것

| 경로 | 쓰는 절 | 내용 |

| `연습/next_token.py` | 3절(읽기) | 다음 토큰 선택(샘플링)과 temperature의 모의 실험. 실제 모델을 부르지 않는다. 현재 API(2026-10-21 판)와 SDK 2.x는 temperature를 요청 인자로 받지 않으므로 개념 설명용이다 |

| `점검표_양식.md` | 8절 | 요구 12개의 점검 방법과 판정 기록 칸, 보강한 13번 요구의 판정 칸. `비교.md`로 복사해 채운다 |

- 회사와 공고는 모두 가상이다. 실제 기업과 관계가 없다.
- 모든 코드는 파이썬 표준 라이브러리만 쓴다. 설치할 패키지가 없다(학생용 `requirements.txt` 없음). 1장에는 가상 환경이 아직 없으므로 Windows의 Git Bash에서는 `python`, macOS에서는 `python3`으로 실행한다(부록 A-5).
- 앞 장이 없으므로 `기준산출물/`은 두지 않는다.
- 이 장에서 실제 모델을 쓰는 곳은 Claude Code의 대화형 세션뿐이다(4절 한 세션, 8절 세 세션). 같은 요청을 되풀이해 보내는 실험은 교수 시연으로 한다.

## 순서

1. 3절: `연습/`의 두 스크립트는 교수가 화면에서 실행한다. 수업 뒤에 직접 실행해 보아도 된다.
2. 4절: `ch01/첫사용/`에서 Claude Code를 처음 쓴다.
3. 8절: `요청문_양식.md`를 `요청문.md`로, `점검표_양식.md`를 `비교.md`로 복사한다. `가_한줄/`과 `나_요구목록/`에서 각각 Claude Code에 요청하고, 점검 명령을 직접 실행해 `비교.md`를 채운다.
4. 8-7절: `점검자료/공고_모두지남.csv`로 (나)의 빈틈을 재현하고, 13번을 더한 요구 목록으로 `다_보강/`에서 다시 만든 뒤 `bash 점검_모아보기.sh 다_보강/dday.py`로 회귀를 확인한다.

## 끝났을 때의 폴더

```text
~/llm-service-lab/ch01/
├── 가_한줄/          (가) 한 줄 요청으로 만든 프로그램
├── 나_요구목록/      (나) 요구 목록 요청으로 만든 dday.py
├── 다_보강/          (다) 13번을 더한 요구 목록으로 다시 만든 dday.py
├── 첫사용/           4절의 연습 결과
├── 연습/  점검자료/  점검_모아보기.sh  (키트에서 받은 것)
├── 요청문.md         세 요청의 실험 조건 기록
└── 비교.md           점검표 판정 기록과 보강의 판정 (이 장의 산출물)
```
