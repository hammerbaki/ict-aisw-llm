## 받는 법

키트 저장소를 1주차에 `~/kits-repo`로 클론해 두었다고 전제한다(부록 A-12-2). 장마다 다음을 실행한다(부록 A-12-3).

```bash
git -C ~/kits-repo pull
mkdir -p ~/kits
cp -rn ~/kits-repo/Service_04장 ~/kits/
```

`~/kits`가 없을 때 `mkdir -p` 없이 복사하면 `~/kits` 자체가 키트 폴더가 된다. 키트 폴더는 원본 사본으로 두고, 쓸 파일은 `~/llm-service-lab/ch04/`로 복사해 고친다.

## 쓰는 순서

명령은 가상 환경을 켠 터미널에서 실행한다(Windows `source ~/llm-service-lab/.venv/Scripts/activate`, macOS `source ~/llm-service-lab/.venv/bin/activate`. 부록 A-13). Windows에서는 `export PYTHONUTF8=1`도 한 번 해 둔다.

1. 0절: `cd ~/kits/Service_04장` 뒤 `python -m pip install -q -r requirements.txt`, `python -m pytest -q`. 학생 키트는 `39 passed, 1 skipped`, 교수용 사본은 `40 passed`가 정상이다.
2. 3-4: `견본/응답_지어낸것.xml`을 `ch04/`로 복사해 값의 꼴을 세는 명령을 익힌다.
3. 5-4, 5-6: `연습/`의 두 파일로 검사기의 출력을 읽고, 교정 연습의 세 문장을 손으로 고친다.
4. 7절(핵심 실습): `양식/`과 `조사/`의 파일을 `ch04/`로 복사해 관찰 기록, 자료 항목표, 조사 기록, 요구사항 명세서를 쓴다.

## 검사기 사용법

```bash
python ~/kits/Service_04장/도구/ears_check.py ch04/요구사항명세서.md --id "REQ-\d{2}"
```

- 종료 코드: 오류 0건이면 0, 오류가 있으면 1(`--strict`이면 경고도 오류로 센다), 파일이 없으면 2.
- 요구 ID의 기본 꼴은 `REQ-001`(두세 자리)이다. 이 장의 명세는 `REQ-01`(두 자리)을 쓰므로 `--id "REQ-\d{2}"`를 준다.
- 주체 이름이 「시스템」이 아니면 `--system 이름`을 준다.
- `--trace`(추적표)와 `--problems`(문제 정의) 선택지가 있으나 이 장에서는 쓰지 않는다.
