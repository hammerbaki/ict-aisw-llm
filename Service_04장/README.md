## 쓰는 순서

키트는 키트 저장소(`~/kits-repo`, 부록 A-12-2)에서 받는다. 명령은 내 PC의 터미널(Windows는 Git Bash, macOS는 기본 터미널)에서 실행하고, 가상 환경을 켠 터미널이면 `python`이 그 환경의 파이썬이다(부록 A-13). 점검기는 표준 라이브러리만 쓰므로 가상 환경 없이도 돈다.

```bash
git -C ~/kits-repo pull
mkdir -p ~/kits
cp -rn ~/kits-repo/Service_04장 ~/kits/
cd ~/llm-service-lab
mkdir -p ch04
for f in 시장조사 경쟁서비스_비교표 포지셔닝 가치제안 출처대조; do
  cp -n ~/kits/Service_04장/${f}_양식.md ch04/${f}.md
done
ls ch04
```

양식을 복사한 직후에는 점검기가 「미통과」를 낸다. 정상이다.

```bash
python ~/kits/Service_04장/도구/check_ch04.py all ch04
```

출처 없는 수치만 찾으려면 `scan`, 주소의 상태 코드를 보려면 링크 점검을 쓴다. 링크 점검은 `curl`을 쓰며, Windows의 Git Bash에 들어 있다.

```bash
python ~/kits/Service_04장/도구/check_ch04.py scan ch04/시장조사.md
bash ~/kits/Service_04장/도구/링크점검.sh ch04/시장조사.md ch04/경쟁서비스_비교표.md
```

## 점검기가 하는 일과 하지 못하는 일

| 하는 일 | 하지 못하는 일 |
|---|---|
| 단위가 붙은 수치에 `[S번호]` 또는 `[가정 A번호]`가 있는지 본다 | 수치가 원문과 같은지 보지 못한다 |
| 출처 표에 주소와 확인 날짜(YYYY-MM-DD)가 있는지 본다 | 주소가 원문을 가리키는지 보지 못한다 |
| 비교표가 서비스 5개, 기능 10행 이상이고 칸이 ○ △ - 인지 본다 | 관찰이 맞는지 보지 못한다 |
| quadrantChart의 점 수와 좌표 범위를 본다 | 점수 규칙이 타당한지 보지 못한다 |
| 출처 기호마다 대조 기록이 있고 판정이 정해진 세 값인지 본다 | 대조를 실제로 했는지 보지 못한다 |

원문 대조는 사람이 한다. 점검기의 「통과」는 형식의 통과다.

## 키트를 고친 뒤

가상 환경은 개인 실습 저장소의 `~/llm-service-lab/.venv` 하나를 쓴다(부록 A-13). `pytest`의 판은 다른 장의 키트와 같은 9.2.0이다. 가상 환경을 켠 터미널에서 실행한다(Windows `source ~/llm-service-lab/.venv/Scripts/activate`, macOS `source ~/llm-service-lab/.venv/bin/activate`).

```bash
python -m pip install -r ~/kits/Service_04장/requirements.txt
cd ~/kits/Service_04장
python -m pytest -q 도구
```

예상 출력: 학생 키트(`교수/` 폴더가 없음)에서는 `14 passed, 1 skipped`, `교수/` 폴더가 있는 교수용 사본에서는 `15 passed`. 건너뛰는 하나는 `교수/견본_ch04/`가 점검기를 통과하는지 보는 테스트이다.
