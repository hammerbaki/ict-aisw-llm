# 요청문 기록 (1장 핵심 실습)

이 파일을 `~/llm-service-lab/ch01/요청문.md`로 복사해 쓴다. 두 요청문은 고치지 않고 그대로 보낸다. 실험의 조건이 사람마다 같아야 결과를 서로 비교할 수 있기 때문이다.

## 실험 조건

| 항목 | 기록 |
|---|---|
| 날짜와 시각 | 「YYYY-MM-DD HH:MM」 |
| Claude Code 버전 (`claude --version`) | 「」 |
| 화면에 표시된 모델 이름 | 「」 |
| 시작할 때의 권한 모드 (화면 아래 표시) | 「예: auto mode on」 |

## (가) 한 줄 요청

`~/llm-service-lab/ch01/가_한줄/`에서 새로 시작한 Claude Code에 보낸다.

```text
채용 공고 마감일을 알려 주는 파이썬 프로그램을 만들어줘.
```

- Claude Code가 되물으면 「알아서 정해줘」라고만 답한다.
- 되물은 질문: 「없음 또는 질문 내용」
- 만들어진 파일: 「`ls` 결과」
- 실행 방법(Claude Code가 알려 준 것 또는 직접 찾은 것): 「」

## (나) 요구 목록 요청

`~/llm-service-lab/ch01/나_요구목록/`에서 새로 시작한 Claude Code에 보낸다. 아래 블록 전체를 한 번에 붙여 넣는다.

```text
채용 공고 마감일 알림 명령줄 프로그램을 dday.py 한 파일로 만들어줘. 아래 요구를 모두 지켜줘.

[입력]
1. 실행 형식은 python dday.py <CSV 파일 경로> [--today YYYY-MM-DD] 이다. 실행 중에 사용자에게 입력을 묻지 않는다.
2. CSV의 첫 줄은 머리글 "회사,공고명,마감일"이고, 마감일은 YYYY-MM-DD 형식이다.
3. --today를 주면 그 날짜를 기준일로 쓰고, 없으면 실행한 날의 날짜를 쓴다.
4. 엑셀에서 "CSV UTF-8"로 저장한 파일(맨 앞에 BOM이 있고 줄 끝이 CRLF)도 읽는다.

[출력]
5. 남은 일수가 적은 공고부터 한 줄에 하나씩 출력한다. 한 줄에는 D-n, 회사, 공고명, 마감일이 이 순서로 들어간다. 마감 당일은 D-n 대신 D-DAY로 쓴다.
6. 남은 일수가 0~3일인 공고는 줄 맨 앞에 [임박]을 붙인다.
7. 마감일이 기준일보다 앞선 공고는 목록에서 빼고, 목록 끝에 "지난 공고 N건"을 한 줄로 쓴다. 지난 공고가 없으면 이 줄을 쓰지 않는다.

[예외]
8. 마감일이 형식에 맞지 않거나 없는 날짜(예: 2027-02-30)인 줄은 건너뛰고 "경고: N번째 줄 마감일 형식 오류 (값)"을 출력한 뒤 나머지를 계속 처리한다. N은 머리글을 1번째 줄로 센 파일의 줄 번호이다.
9. 파일이 없으면 "오류: 파일을 찾을 수 없습니다: <경로>" 한 줄을 출력하고 종료 코드 1로 끝낸다. 파이썬 Traceback을 보이지 않는다.
10. 표시할 공고가 하나도 없으면 "표시할 공고가 없습니다."를 출력한다.

[제약]
11. 파이썬 3.12 이상의 표준 라이브러리만 쓴다. 외부 패키지를 설치하지 않는다.
12. 공고 목록은 표준 출력(stdout)으로, 경고와 오류는 표준 오류(stderr)로 낸다.

다 만들면 실행 방법을 한 줄로 알려줘.
```

- Claude Code가 되물으면 「요구 목록에 있는 대로 하고, 없는 것은 알아서 정해줘」라고만 답한다.
- 되물은 질문: 「없음 또는 질문 내용」
- 만들어진 파일: 「`ls` 결과」

## 지키는 규칙

1. 세 요청은 서로 다른 폴더에서, 각각 새 Claude Code 세션으로 보낸다. 앞의 대화가 뒤의 결과에 섞이지 않게 하기 위해서이다.
2. 결과를 본 뒤 고쳐 달라고 하지 않는다. 한 번 요청한 결과 그대로를 점검한다. 실행 방법을 묻는 것은 허용한다.
3. 점검 자료(`점검자료/`)를 Claude Code에 보여 주지 않는다. 점검 기준을 미리 알려 주면 비교가 성립하지 않는다.
