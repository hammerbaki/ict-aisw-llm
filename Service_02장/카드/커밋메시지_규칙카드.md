# 커밋 메시지 규칙 카드

근거: Pro Git 2판 5.2절 「Commit Guidelines」(<https://git-scm.com/book/en/v2/Distributed-Git-Contributing-to-a-Project>, 2026-11-14 확인). 한국어 제목의 끝맺음은 이 과목의 규칙이다.

## 모양

```text
제목 한 줄 (50자 이내, 마침표 없음)
(빈 줄)
본문: 무엇을 왜 바꾸었는가. 한 줄 72자 안팎에서 줄을 바꾼다.
```

- 짧은 커밋은 제목만으로 충분하다: `git commit -m "제목"`
- 본문이 필요하면 `-m`을 두 번 쓴다: `git commit -m "제목" -m "본문"`
- 편집기로 쓰려면 `-m` 없이 `git commit`을 실행한다(편집기는 `git config --global core.editor`로 정한다).

## 규칙 다섯

| 규칙 | 좋은 예 | 나쁜 예 |
|---|---|---|
| 제목은 무엇을 바꾸었는지 명사형으로 끝낸다 | `출력 순서를 마감일 순으로 정렬` | `수정함`, `고쳤습니다` |
| 커밋 하나에 변경 하나 | `D-day 표기: 마감 당일은 D-DAY` | `표기 바꾸고 정렬하고 README 씀` |
| 제목만 읽어도 다른 커밋과 구별된다 | `deadline README 작성: 실행법, CSV 형식` | `README`, `update` |
| 까닭은 본문에 쓴다 | 본문: `지난 공고를 D+n으로 보이면 지원할 수 있는 것처럼 읽힌다.` | 제목에 까닭까지 몰아 쓰기 |
| 도구 이름보다 결과를 쓴다 | `CLAUDE.md 작성: 실행 명령과 작업 규칙` | `Claude가 한 것` |

## 커밋하기 전 세 가지

1. `git diff --staged --stat`: 넣으려는 파일이 맞는가
2. `git diff --staged`: 넣으려는 줄이 맞는가, 비밀 정보가 없는가
3. `git diff --check`: 줄 끝 공백 같은 실수가 없는가

## 자동으로 만들어지는 메시지

| 명령 | 만들어지는 제목 |
|---|---|
| `git revert <커밋>` | `Revert "<원래 제목>"` (본문: `This reverts commit <해시>.`) |
| `git merge --no-ff <브랜치>` | `Merge branch '<브랜치>'` |
| `git pull` (병합이 생길 때) | `Merge branch 'main' of <원격 주소>` |

자동 메시지는 그대로 두어도 된다. 되돌린 까닭은 `git revert --edit`(기본)로 열리는 편집기에서 본문에 더한다.
