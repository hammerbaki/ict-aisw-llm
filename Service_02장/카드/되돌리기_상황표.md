# 상황별 되돌리기 표

근거: git-restore, git-revert, git-reset 참조 문서(<https://git-scm.com/docs>), Pro Git 2판 2.4절 「되돌리기」, Claude Code Checkpointing 문서(<https://code.claude.com/docs/en/checkpointing>). 2026-11-14 확인.

먼저 `git status`로 지금 어느 영역에 변경이 있는지 본다. 그다음 아래 표에서 상황을 고른다.

## 1. 아직 커밋하지 않은 변경

| 상황 | 명령 | 결과 | 주의 |
|---|---|---|---|
| 파일을 고쳤는데 고치기 전으로 돌리고 싶다 | `git restore <파일>` | 작업 트리가 스테이징 영역(없으면 마지막 커밋)의 내용으로 돌아간다 | 고친 내용은 되찾을 수 없다 |
| `git add`를 했는데 빼고 싶다 | `git restore --staged <파일>` | 스테이징에서 빠진다. 파일 내용은 그대로 | 안전하다 |
| Claude Code가 편집 도구로 고친 것을 대화째 되돌리고 싶다 | `Esc` 두 번 또는 `/rewind` → Restore code | 그 프롬프트 직전의 파일 내용으로 | 셸 명령으로만 바뀐 파일은 돌아오지 않는다 |
| Claude Code가 셸 명령으로 만든 파일을 지우고 싶다 | `git status`로 확인 뒤 `rm <파일>` 또는 `git restore <파일>` | 새 파일은 지우고, 추적하던 파일은 되돌린다 | `git clean -fd`는 추적하지 않는 파일을 모두 지운다. 쓰지 않는다 |

## 2. 커밋했지만 아직 푸시하지 않은 변경

| 상황 | 명령 | 결과 | 주의 |
|---|---|---|---|
| 방금 커밋의 메시지가 틀렸다 | `git commit --amend -m "새 메시지"` | 마지막 커밋이 새 커밋으로 바뀐다 | 푸시한 커밋에는 쓰지 않는다 |
| 방금 커밋에 파일 하나를 빠뜨렸다 | `git add <파일>` 뒤 `git commit --amend --no-edit` | 마지막 커밋에 파일이 더해진다 | 같음 |
| 마지막 커밋을 취소하고 변경은 스테이징에 남기고 싶다 | `git reset --soft HEAD~1` | 커밋만 없어지고 변경은 스테이징에 | 같음 |
| 마지막 커밋을 취소하고 변경은 작업 트리에 남기고 싶다 | `git reset HEAD~1` (`--mixed`) | 커밋과 스테이징이 없어지고 파일은 그대로 | 같음 |

## 3. 이미 푸시했거나, 기록을 남기며 되돌리고 싶은 변경

| 상황 | 명령 | 결과 | 주의 |
|---|---|---|---|
| 특정 커밋의 변경만 취소하고 싶다 | `git revert <커밋>` | 그 변경을 거꾸로 적용한 새 커밋이 생긴다 | 작업 트리가 깨끗해야 한다. 기록은 지워지지 않는다 |
| 특정 파일만 예전 커밋의 내용으로 | `git restore --source=<커밋> <파일>` 뒤 커밋 | 그 파일만 예전 내용으로 | 다른 파일은 그대로 |

## 4. 쓰지 않는 명령 (이 과목의 개인 저장소에서)

| 명령 | 까닭 |
|---|---|
| `git reset --hard <커밋>` | 커밋하지 않은 변경을 지우고, 추적하지 않는 파일도 덮어쓸 수 있다. 푸시한 커밋을 지우면 원격과 어긋난다 |
| `git push --force` | 원격의 기록을 덮어쓴다. 팀 저장소에서는 다른 사람의 커밋이 사라진다 |
| `git clean -fd` | 추적하지 않는 파일과 폴더를 모두 지운다 |
| `git checkout -- .`, `git restore .` | 작업 트리의 모든 변경을 한 번에 버린다 |

잘못 실행했다면 `git reflog`로 HEAD가 지나온 커밋을 찾는다. 커밋한 적이 있는 내용은 대개 되찾을 수 있다. 커밋한 적이 없는 내용은 Git으로 되찾을 수 없다.

## 5. 비밀 정보를 커밋했다

1. **키를 먼저 폐기하고 새로 발급한다.** 기록에서 지우는 것보다 먼저다(GitHub Docs 「Removing sensitive data from a repository」).
2. `git rm --cached <파일>`로 추적에서 빼고 `.gitignore`에 넣어 커밋한다. 파일은 디스크에 남는다.
3. 앞선 커밋에는 여전히 남아 있다(`git log --all -- <파일>`로 보인다). 푸시하지 않았다면 교수에게 알리고 함께 정리한다.
