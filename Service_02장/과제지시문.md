# 2장 핵심 실습 과제 지시문

개인 실습 저장소 `~/llm-service-lab`에서 Claude Code에게 작은 변경 세 가지를 한꺼번에 시키고, 그 변경을 사람이 `git diff`로 읽어 커밋 셋으로 나누어 기록한다. 셋 가운데 사용자의 요구를 깨뜨린 변경 하나를 diff에서 찾아 `git revert`로 되돌리고, 기록을 GitHub의 개인 저장소에 푸시한다.

대상 프로그램은 키트의 `골격/deadline/`이다. 지원 일정 CSV를 읽어 공고마다 마감까지 남은 날을 보여 준다. CSV의 순서는 사용자가 정한 지원 우선순위이다(`deadline.py`의 `render` 설명, 테스트 `test_render_keeps_csv_order`).

- **만드는 것.** `CLAUDE.md`, 변경 셋의 커밋, 되돌리기 커밋, `ch02/작업기록.md`, GitHub의 원격 저장소.
- **해결하는 문제.** 변경 2(마감일 순 정렬)가 요구를 지키던 테스트와 함께 요구를 없앤다. 테스트 결과와 보고에는 나타나지 않고 diff에만 나타난다.

## 1. Claude Code에 보내는 지시

Claude Code는 가상 환경을 켠 터미널의 저장소 맨 위에서 `claude --permission-mode manual -n ch02-main`으로 시작한다.

### 지시 A: 변경 세 가지 (계획 모드에서 보낸다)

```text
@ch02/deadline/deadline.py @ch02/deadline/dday.py 를 읽고 다음 세 가지를 바꾸는 계획을 세워라.
1. dday.py: 마감 당일은 "D-DAY", 마감일이 지난 공고는 "마감"으로 표시한다.
2. deadline.py: 출력 순서를 마감일이 빠른 순으로 바꾼다.
3. ch02/deadline/README.md를 새로 만든다. 실행법, CSV 형식, 표기를 적는다.
변경 1과 2는 tests/ 아래의 해당 테스트 파일에 테스트를 추가하거나 고친다.
테스트는 ch02/deadline 폴더에서 python -m pytest -q 로 실행한다.
커밋은 하지 마라.
```

### [선택] 지시 B: 정렬 옵션 (Manual 모드에서 보낸다)

```text
ch02/deadline/deadline.py에 --sort 옵션을 추가하라.
- 값은 csv와 deadline 둘이다. 기본값은 csv이고, 이때는 CSV 순서를 그대로 둔다.
- deadline이면 마감일이 빠른 순으로 보여 준다.
- tests/test_deadline.py에 deadline 정렬 테스트를 추가한다. 기존 test_render_keeps_csv_order는 고치지 마라.
- README.md의 실행 예에 --sort deadline 한 줄을 더한다.
테스트를 실행해 결과를 보여 주라. 커밋은 하지 마라.
```

### [선택] 지시 C: 커밋 맡기기 (지시 B의 결과를 확인한 뒤)

```text
ch02/deadline 아래의 변경만 커밋하라. ch02/작업기록.md는 커밋에 넣지 마라.
메시지는 CLAUDE.md의 커밋 메시지 규칙을 따른다. 커밋한 뒤 git show --stat HEAD 의 결과를 보여 주라.
```

## 2. 커밋 계획

| 순서 | 커밋 | 들어갈 파일 | 누가 | 절 |
|---|---|---|---|---|
| 1 | 1장 결과물과 .gitignore | `.gitignore`, `ch01/` | 사람 | 3-4 |
| 2 | 실습 골격 | `ch02/deadline/` | 사람 | 4-1 |
| 3 | CLAUDE.md | `CLAUDE.md` | 사람 | 10-2 |
| 4 | 변경 1: D-day 표기 | `dday.py`, `tests/test_dday.py` | 사람 | 10-7 |
| 5 | 변경 2: 마감일 순 정렬 | `deadline.py`, `tests/test_deadline.py` | 사람 | 10-7 |
| 6 | 변경 3: README | `README.md` | 사람 | 10-7 |
| 7 | 변경 2의 되돌리기 | `git revert`가 만든다 | 사람 | 10-8 |
| 8 | 작업기록 | `ch02/작업기록.md` | 사람 | 10-9 |
| (선택) 9 | 정렬 옵션 | `deadline.py`, `tests/test_deadline.py`, `README.md` | Claude Code, 사람이 점검 | 과제지시문 9(선택) |

첫 푸시는 커밋 2 뒤(9-2), 마지막 푸시는 커밋 8 뒤(10-9)에 한다.

## 3. 완료 기준

1. `git log --oneline`의 맨 위가 다음 모양이다(해시와 메시지는 달라도 된다).

```text
* 작업기록 커밋
* Revert "…정렬…"
* README 커밋
* 정렬 커밋
* D-day 표기 커밋
* CLAUDE.md 커밋
* …
```

2. `git status`가 `Your branch is up to date with 'origin/main'.`을 보인다.
3. GitHub의 저장소 화면에 `ch01/`, `ch02/`, `CLAUDE.md`, `.gitignore`가 보이고 커밋 수가 로컬과 같다.
4. 가상 환경을 켠 터미널에서 `python ~/kits/Service_02장/도구/check_ch02.py ~/llm-service-lab`이 `20/20 통과`를 출력한다.
