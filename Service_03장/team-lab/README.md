# 팀 실습 저장소

「LLM 서비스 개발」 3장의 팀 실습 저장소다. 팀원 3~4명이 이슈, 브랜치, 풀 리퀘스트, 리뷰, 병합의 흐름을 한 사람씩 한 바퀴 돌고, 정해 둔 줄에서 병합 충돌을 만들어 해결한다. 13장에서는 사용성 평가에서 찾은 문제를 이 저장소의 이슈로 등록할 때 다시 쓴다.

## 파일

| 경로 | 쓰임 |
|---|---|
| `members/_양식.md` | 팀원 소개 파일의 양식. 1단계에서 각자 `members/<GitHub 아이디>.md`로 복사해 채운다 |
| `서비스소개.md` | 2단계(충돌 실습)에서 두 사람이 같은 줄을 고치는 파일 |
| `.github/ISSUE_TEMPLATE/task.md` | 이슈 양식. 이슈를 만들 때 「작업 이슈」를 고르면 본문이 채워진다 |
| `.github/pull_request_template.md` | 풀 리퀘스트 설명 양식 |

## 작업 규칙

1. `main`에 직접 커밋하지 않는다. 모든 변경은 이슈 → 브랜치 → 풀 리퀘스트 → 리뷰 → 병합으로 들어온다.
2. 브랜치 이름은 `<이슈 번호>-<동사>-<대상>`으로 짓는다. 예: `3-add-member-hong`.
3. 풀 리퀘스트 설명에는 `Closes #<이슈 번호>`를 적는다.
4. 승인(Approve) 하나를 받은 뒤 작성자가 병합한다. 이 저장소에서는 병합 방식으로 「Create a merge commit」만 쓴다.
5. 브랜치를 만들기 전과 푸시하기 전에 `git fetch`와 `git pull`로 원격의 최신 상태를 받는다.
6. 강제 푸시(`git push --force`)를 하지 않는다.
7. 저장소는 각자 `~/teams/<팀>-lab`에 클론한다. 개인 실습 저장소(`~/llm-service-lab`) 안에 클론하지 않는다.
8. 각자 자기 아이디의 자리(`members/<아이디>.md`)에만 파일을 더한다. 이슈는 누구나 열 수 있다(13장의 사용성 문제 이슈는 라벨 `usability`).

## 팀원

팀원 목록은 `members/` 폴더의 파일로 대신한다. 이 표에 직접 이름을 덧붙이지 않는다(여러 사람이 같은 자리에 줄을 더하면 충돌이 난다).
